# 盲點紅隊審查 (Blind-Spot Audit)

## 這個 skill 在做什麼,為什麼這樣設計

一個人開發投資系統最大的風險是「同溫層思考」:你愛上自己的 thesis,證據只挑支持的,
量化只回測會贏的。單一個 reviewer(包括 LLM)給的批評會同質化、空泛(「可以多考慮風險」)。

真正能撈出盲點的方法是**讓審查者戴上幾個彼此會吵架的角色**,每個角色被強迫對著規劃的
**具體某一句/某個決定**開火,而不是泛泛而談。本 skill 就是把這套多視角紅隊流程固定下來。

核心鐵律(整份審查都遵守):
1. **每條批評必須引用被審文件的具體段落或決定**。不能是「建議加強風控」,要是
   「你的 CLAUDE.md L4 把 concentration_score 設為衍生值,但沒定義衍生公式的時間窗,
   季度 vs 年度市占會給出完全不同的瓶頸排名」。沒有錨點的批評直接丟掉。
2. **每條批評附一個可證偽 / 可驗證的方式**——怎麼知道這個盲點是真的、何時會爆。
3. **批評要能行動**。指出洞之外,給一個具體下一步。
4. 寧可少而尖,不要多而鈍。撈不到具體的,就說「這個視角沒撈到東西」,不要硬湊。

## 流程

1. **讀目標**:讀使用者指定的規劃 / thesis / .md。若有專案記憶(如 CLAUDE.md)一併讀,
   因為盲點常藏在「已定案」的假設裡。標出文件裡的關鍵主張、已定案決定、隱含假設。
2. **逐 lens 開火**:對下面每個 lens,強迫至少產出一條錨定到具體段落的批評(撈不到就明說)。
3. **排嚴重度**:每條標 🔴 高 / 🟡 中 / ⚪ 低。高 = 會讓投資結論整個錯;中 = 會讓某個訊號失真;
   低 = 衛生問題。
4. **產出報告**(格式見下),最後給「最危險的三個盲點」+ 整體可證偽條件 + 接下來盯什麼。

## 審查視角 (Lenses)

### A. 產業分析 / thesis

**A1 證偽官 (Falsifier)** — 每條 thesis/claim 有沒有夠硬的 `disproof_condition`?
找出「無法被證偽」的主張(怎樣都能自圓其說的論述)。對著最核心的那條 thesis 問:
「什麼真實世界的觀測會讓我承認這條錯了?如果答不出來,它就不是 thesis,是信仰。」

**A2 反身性 / 已被定價 (Reflexivity / Already-priced)** — 你挖到的瓶頸/edge,市場是不是
早就知道了?你的「variant perception」(與市場共識不同的地方)具體是什麼?如果你的結論
跟賣方研究一致,alpha 在哪?注意:正確 ≠ 有利可圖,正確且非共識才有利可圖。

**A3 證據稽核 (Evidence auditor)** — 來源獨立性(看似多來源其實互相抄、同一個原始 PR);
證據分級有沒有灌水(把產業報導當一手);時間落差(用兩年前的供應鏈結構推今天);
倖存者偏誤(只研究還活著的贏家);**LLM 從類別詞幻覺出具體實體**(這份專案 L6 Gap 4 踩過)。

**A4 瓶頸壓力測試 (Chokepoint stress)** — 你認定的瓶頸真的會「斷」嗎?壓測:第二供應源、
客戶自製、技術替代路徑、需求其實是 tech-push 而非 confirmed demand-pull。瓶頸的 alpha 在
「一條關係會不會斷」,不在點上(本專案 L4)。對著最關鍵那條供應邊問:它斷了誰最痛、多久能補。

**A5 敘事 vs 數字 (Narrative vs numbers)** — 質化圖譜訊號有沒有硬數字背書(營收、capex、
訂單、產能利用率、客戶集中度)?還是一個漂亮故事缺財務落點?對照 CLAUDE.md 的核驗清單
(客戶集中度 / 毛利 / backlog / 稀釋 / 估值)有沒有真的會被執行,還是只寫在規劃裡沒進 pipeline。

### B. 量化 / 交易

**B6 回測誠實官 (Backtest honesty)** — look-ahead bias(用了當時拿不到的資料)、survivorship、
過擬合、多重檢定 / p-hacking(試了 50 個因子挑最好的)、樣本內外沒分、交易成本 / 滑價 /
流動性 / 借券成本沒算進去。問:這個策略的 Sharpe 扣掉成本、做了樣本外、會剩多少。

**B7 Regime 依賴** — 策略只在某種市場狀態有效?回測期間是不是剛好一個大多頭 / 一個利率環境。
換 regime(升息→降息、AI 退潮)還活著嗎?有沒有隱含的宏觀因子曝險沒被認出來。

**B8 訊號落地縫隙 (Signal-to-trade gap)** — 這是最容易被忽略的盲點:知識圖譜 / thesis 的
**質化訊號,具體怎麼變成一個可交易的部位**?進場條件、持有期、出場 / 停損、調倉頻率是什麼?
如果答不出「圖譜更新了一條邊 → 我該買多少 / 賣多少」,那引擎 A 和交易其實沒接上。

**B9 風控 / 部位 (Risk & sizing)** — 單一標的集中度、標的間相關性(都押 AI 供應鏈 =
一個 factor 重押)、最大回撤忍受度、thesis 被推翻時的退出機制、部位 sizing 規則
(等權?凱利?波動度倒數?)。沒有 sizing 規則的「投資建議」只是選股清單。

### C. 元層 (Meta)

**C10 系統整合縫隙 (Integration seams)** — 引擎 A(科研)/ B(SNS)/ C(基本面)之間的交接
有沒有定義?三個引擎是真的會匯流成一個投資結論,還是各跑各的、最後靠人腦硬湊?
特別查:B 的線索怎麼觸發 A、A 的圖譜怎麼餵 C 的估值、誰是最後拍板的那一層。

**C11 單一視角風險 (Monoculture)** — 方法論藍圖(如 chokepoint-atlas)若是「單一視角」
(本專案明寫:偏小市值瓶頸獵手、高風險),整個系統會不會繼承這個偏誤,
把所有標的都看成「被低估的瓶頸」?哪裡需要第二個 lens(價值 / 成長 / 宏觀)來平衡。

**C12 可操作性 / scope (Tractability)** — 野心 vs 真實資源(單人、本機、時間)。
哪些是過度設計、現在不該做;第一條垂直切片是否真的最小可驗證;有沒有把「能跑」
誤當成「會賺」。

## 輸出格式

ALWAYS 用這個結構,並以**繁體中文**輸出:

```
# 盲點審查報告:<被審對象>

## 最危險的三個盲點 (先看這個)
1. 🔴 <一句話盲點> — <為什麼這會讓投資結論整個錯>
2. 🔴/🟡 ...
3. ...

## 逐視角發現
### A1 證偽官
- [🔴/🟡/⚪] **觀察**:<引用 plan 具體段落 / 決定>
  **為何是盲點**:<推理>
  **修正**:<具體下一步>
  **怎麼驗證 / 何時會爆**:<可證偽條件>
(每個有撈到東西的 lens 都列;沒撈到的寫「此視角未發現重大盲點」)

## 整體可證偽條件
<這份規劃整體的核心假設;什麼真實觀測會推翻它>

## 接下來盯什麼
<3-5 個最該先補 / 先驗證的動作,按優先序>
```

## 反面教材(避免)

- ❌「建議多考慮風險管理」— 空泛,沒錨點。
- ❌「資料品質很重要」— 廢話。
- ✅「你 plan 裡引擎 C 只寫『爬客觀數字出建議』,但沒定義從數字到部位 sizing 的規則,
  等於有選股沒有下單邏輯 → 建議先定義最小版:單檔上限 X%、thesis 失效即出場。」

如果整份規劃寫得很好、某些 lens 真的撈不到洞,誠實說出來——假裝有問題比漏掉真問題更糟。
