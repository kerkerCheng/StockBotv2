# 盲點紅隊審查 — Research Review Profile

## 這個 skill 在做什麼

一個人做投資研究最大的風險是同溫層思考：愛上自己的 thesis、證據只挑支持的。單一 reviewer
（包括 LLM）給的批評會同質化、空泛（「可以多考慮風險」）。真正能撈出盲點的方法是**讓審查者
戴上幾個彼此會吵架的角色**，每個角色被強迫對著**具體某一句判斷**開火。

**本檔是三個 review profile 之一（research）。** 另外兩個（development／operational）住
[`skills/development-flow/SKILL.md`](../development-flow/SKILL.md)；流程模型住
[`docs/AGENT_WORKFLOW.md`](../../docs/AGENT_WORKFLOW.md)。**不要每次全跑三個 profile。**

核心鐵律（整份審查都遵守）：

1. **每條批評必須引用被審對象的具體段落或決定。** 沒有錨點的批評直接丟掉。
2. **每條批評附一個可證偽／可驗證的方式**——怎麼知道這個盲點是真的、何時會爆。
3. **批評要能行動。** 指出洞之外，給一個具體下一步。
4. 寧可少而尖，不要多而鈍。撈不到具體的就說「這個視角沒撈到東西」，不要硬湊。

## 流程

1. **讀目標**：讀使用者指定的 thesis／研究筆記／排序理由。標出關鍵主張、已定案決定、隱含假設。
2. **逐 lens 開火**：對下面每個 lens，強迫至少產出一條錨定到具體判斷的批評（撈不到就明說）。
3. **排嚴重度**：🔴 高（會讓投資結論整個錯）／🟡 中（會讓某個判讀失真）／⚪ 低（衛生問題）。
4. **產出報告**（格式見下），最後給「最危險的三個盲點」＋整體可證偽條件＋接下來盯什麼。

## 審查視角（Lenses）

### A1 證偽官（Falsifier）

每條 thesis／claim 有沒有夠硬的 `disproof_condition`？找出「無法被證偽」的主張——怎樣都能
自圓其說的論述。對著最核心的那條問：**什麼真實世界的觀測會讓我承認這條錯了？**

⚠ 光是填了 `disproof_condition` **不算數**（L7）：每條反證必須附**核查頻率**與**觸發後 48
小時要做什麼**，否則它是一個永遠不會響的火警警報。

⚠ **進場靠判斷，出場靠 disproof。** 反證的用途是決定何時承認判斷錯了，**不是進場的前置條件**；
混用會產生「永遠不出手、只累積反證」的無效產出。看到「證據還不夠所以不排序」時，這條 lens
該開火的方向是**要求排序**，不是要求更多反證。

### A2 共識與 expectation gap 的語意（Consensus semantics）

> **Convergence without differentiated evidence is healthy.**
> 我們的判斷與市場共識一致，本身**不是**缺陷。不得為了「顯得有 alpha」逼內部預測人為偏離共識。

該審的是**語意是否成立**，不是方向是否不同：

- 有沒有把「便宜」誤當成 expectation gap？倍數同時被「分析師改估計」與「股價漲跌」推動——
  被審的判斷有沒有把這兩件事分開？
- 成長率的比較有沒有跨越單位／口徑？（營收成長 ≠ EPS 隱含成長；兩者的差包含利潤率預期，
  **那個差不是 gap**。）
- 絕對值有沒有被跨標的比較？以報價單位或報表幣別計的量只能比同一標的的時間序列。

**只有在系統自己聲稱「這裡有 variant perception」時**，才驗整條鏈：
`graph／evidence → differentiated assumption → model expression → forecast／valuation impact`。
鏈斷在哪一節就報哪一節。沒有聲稱 variant perception 的判斷，不套這條。

### A3 證據稽核（Evidence auditor）

- **來源獨立性**：看似多來源其實互相抄、同源於一個原始 PR。文件選源至少 3 個不同 `origin_entity`；
  「被分析的公司自己的文件」只能算佐證，不能算主要確認來源（L8）。
- **證據分級有沒有灌水**：把產業報導當一手；把「公司自揭 material uncertainty」寫成「審計出具
  保留意見」——具體審計／法律術語的措辭精度本身就是一個 claim（L11-1）。
- **時間落差**：用兩年前的供應鏈結構推今天。
- **倖存者偏誤**：只研究還活著的贏家。
- **LLM 從類別詞幻覺出具體實體**：quote 裡沒有逐字出現的型號／公司名，就是幻覺（L6 Gap 4）。
- **「我找不到」≠「它不存在」**（L11-5）。解讀「沒命中」之前先問：**如果答案存在，它會出現在
  我手上這份文件的哪一節？** 答不出來就別解讀 0。

⚠ **注意會隨研究量單調上升的指標**：evidence 等級、同一 chokepoint 的供應商計數、documents 計數。
它們測的是「我們讀了多少」，不是「世界是什麼樣」。看到有人拿它們當瓶頸性證據就開火。

### A4 瓶頸壓力測試：可替代性與時序（Substitutability & timing）

認定的瓶頸真的會「斷」嗎？壓測四條：第二供應源、客戶自製、技術替代路徑、
**需求其實是 tech-push 而非 confirmed demand-pull**。

**瓶頸的 alpha 大半在邊上，不在點上**（L4）。對著最關鍵那條供應邊問：**它斷了誰最痛、多久能補？**
補的時間（lead time）缺席時，要報「時序未知」，不要套「供應鏈大概一季」這種預設。

`sole_source` 的確認來源必須是**客戶端或第三方**；供應商自稱只能算弱證據。

### A5 敘事 vs 數字（Narrative vs numbers）

質化圖譜訊號有沒有硬數字背書？出投資建議前的核驗清單五項有沒有真的被執行過，還是只寫在計畫裡：
**客戶集中度、毛利率／產能利用率、backlog／營收結構、稀釋、估值壓力**。

一個漂亮故事缺財務落點，就是 🔴。

### A6 假設出處（Assumption provenance）

估值與預測裡的**每一個數字**，出處是哪裡？分三類逐一標記：

1. **來自證據**（指得回一份可逐字核對的文件）
2. **來自共識**（那是校準參考，不是我們的判斷）
3. **來自研究者自己填的**（最危險的一類——它會讓模型看起來有根據，其實是自己的直覺）

第 3 類沒有被明確標出來，就是 🔴。**支持性引用與校準性引用不可混為一談**：拿共識當「證據」
會讓「我們與市場的差異」在算式裡自己消失。

### A7 thesis → model expression

thesis 說的那件事，**在模型裡表現成哪一個數字？** 常見斷點：

- thesis 講「客戶要 qualify 第二供應源」，模型裡卻沒有任何一格因此改變 → 那條 thesis 對估值零貢獻。
- 模型的敏感度最大的那一格，thesis 從來沒提過 → 真正在決定結論的不是我們研究的東西。

判準：**把 thesis 刪掉，模型輸出會變嗎？** 不會變就報 🔴。

### A8 相關性與退出（Correlation & exit）

- **候選之間的相關性**：本圖標的高度集中於 AI 光互連。列出 N 檔**不等於** N 個獨立機會——
  全買是同一個賭注下 N 次。被審的判斷有沒有講明這件事？
- **alpha 與 beta 是同一個賭注**：兩個 sleeve 的目標比例分開寫，不代表它們是兩個獨立風險來源。
- **thesis 被推翻時的退出機制**：誰會發現、多久發現、發現後做什麼。

⚠ **不要在這條 lens 裡重算部位尺寸或資本上限。** 系統不給部位尺寸；資本閘門是否 binding
由 `python -m audit invariants --only GateDiscrimination` 機械回答，不由人工重算。
這條 lens 只審**判斷的獨立性與退出路徑**。

### C11 單一視角風險（Monoculture）

方法論藍圖若是單一視角（偏小市值瓶頸獵手、高風險），整個研究會不會繼承這個偏誤，
把所有標的都看成「被低估的瓶頸」？哪裡需要第二個 lens（價值／成長／宏觀）來平衡？

## 輸出格式

ALWAYS 用這個結構，並以**繁體中文**輸出：

```
# 盲點審查報告：<被審對象>

## 最危險的三個盲點（先看這個）
1. 🔴 <一句話盲點> — <為什麼這會讓投資結論整個錯>
2. 🔴/🟡 ...
3. ...

## 逐視角發現
### A1 證偽官
- [🔴/🟡/⚪] **觀察**：<引用具體段落／決定>
  **為何是盲點**：<推理>
  **修正**：<具體下一步>
  **怎麼驗證／何時會爆**：<可證偽條件>
（每個有撈到東西的 lens 都列；沒撈到的寫「此視角未發現重大盲點」）

## 整體可證偽條件
<這份判斷整體的核心假設；什麼真實觀測會推翻它>

## 接下來盯什麼
<3–5 個最該先補／先驗證的動作，按優先序>
```

## 反面教材（避免）

- ❌「建議多考慮風險管理」— 空泛，沒錨點。
- ❌「資料品質很重要」— 廢話。
- ❌「你的結論跟賣方一致，所以沒有 alpha」— **已退役的 framing**。一致本身不是缺陷；
  該問的是語意是否成立、假設出處是否誠實。
- ❌「還沒有 outcome 驗證，所以不該排序」— 那是死循環，不是批評。
- ✅「A6：`fair value` 用的毛利率 42% 在三個 evidence ref 裡都找不到，最接近的一份寫的是
  『管理層目標區間 38–40%』——這是第 3 類（研究者自填）卻標成第 1 類。驗證方式：把它調回 39%
  重算，看 implied return 是否還在門檻之上。」
- ✅「A4：認定 X 是 sole source 的三份引用 `origin_entity` 全是 X 自己。依 L8 這只能算
  `verified_by_absence`。驗證方式：找客戶端法說會或第三方供應商名單，找不到就把該邊降級。」

如果整份判斷寫得很好、某些 lens 真的撈不到洞，**誠實說出來**——假裝有問題比漏掉真問題更糟。
