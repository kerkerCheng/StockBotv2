# 劇本卡的事件表（事件字彙 v1、兩把尺）

> 2026-11-23｜載體：Phase 8 第二個修正案「劇本時間線」（[設計稿](../../../brainstorms/2026-11-21-playbook-replay-design-v3.md)檔尾 2026-11-23 第四到第六則）第 1 步。
> 這張表把六張劇本卡上 A3、B1–B5 的每一列對到同一組事件種類，並換成「從起點起算第幾個月」。**種類是人標的、月數是程式算的**；卡上的原句、鍵、出處不動，這裡只引位置。
> 它跟卡一樣是描述：六段都是有漲起來的、每段一家代表公司。看得到的排列是觀察，不是規則，也不是基準率——基準率在 [H17 的回測](../../phase7/registration.md)。

## 事件字彙 v1（封閉；加一種＝升版）

| 代碼 | 白話 | 記在哪一本帳 | 收什麼 |
|---|---|---|---|

| `supplier_raise` | 供應商籌錢 | 層 | 發股、發債、授信 |
| `terms_turn` | 價格或合約條件轉向 | 層 | 漲價停止、降價、長約重議、交期恢復、合約裡的價格上限 |

- 草稿是八種（設計稿第四則）。標完六張卡之後加了兩種：**買家上修**（卡 6 的買家口徑全是往上調，原本只有「改口」放不進去）與**供應商下修**（產能時程延後、財測下修、認列損失，跟價格與合約條件不是同一件事）。
- 數字鐘不在字彙裡：營收年增轉正與轉負、毛利率高低點季由財報數字算（卡的 A5、C3）。

## 兩把尺

- **文件尺**：第 0 個月＝這一段最早的一筆「硬訊號」或「買家綁產能」的發布月，不論誰說的；誰說的照標。買家或第三方最早的一筆另外標出來——供應商自述不能當「自己是瓶頸」的獨立佐證（L8），兩個起點差幾個月本身就是資訊。
- **數字尺**：第 0 個月＝代表公司「營收年增連續為正」那一段的第一個月（卡的 A5；海外公司用季，取季底月）。回測的事件表只接得上這一把（它不讀文件）。
- 兩把都印，不合成一個數。高點月是事後才知道的，只用來看舊劇本的事件落在高點前後哪裡；進行中的層沒有這一欄可用。
- 設計稿第四則的草稿寫「買家或第三方寫的優先」。標完之後改成「最早的一筆當起點、買家或第三方最早的另標」：照草稿，矽晶圓那一段的起點會落在高點前 3 個月，尺就沒有用了。這是看過六張卡的高點才定的，照實寫在這裡。

看得到的排列（五段走完的；觀察，不是規則）：

- **買家或第三方第一次寫出硬訊號或綁產能**，離高點 -11、-1、-3、+1 個月（4 段有）：3 段在高點前三個月以內或高點之後。在卡上抓到的文件裡，客戶端的印證多半到了高點附近才出現（卡上沒抓的更早文件不算在內，見各卡 D2）。
- **買家改口**第一次出現，離高點 +2、+19、-3、+12、+13 個月（5 段有）：4 段在高點之後。
- **價格或合約條件轉向**第一次出現，離高點 +12、+17、+22 個月（3 段有）；**供應商下修** +2、+12、+19 個月（3 段有）：都在高點之後。

## 讀這張表要知道的

- 種類是一個人標的，沒有第二個人核；一列只給一種，同一份文件的兩個面向（例：買家出錢養第二來源）分在兩列。
- 日期是文件的發布日。年報裡事後寫的事（例：預付發生在前一年）用的是年報的發布日，所以在尺上偏晚。
- 卡上沒抓的文件不會出現在這裡：某一種事件是「—」，可能是沒發生，也可能是沒抓（各卡的 D2）。
- 每段一家代表公司；換一家，數字尺與高點月都會動。
