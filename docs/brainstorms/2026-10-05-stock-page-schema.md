## 0. 一句話

個股頁從「看著聯亞手刻的版面」改成「由 schema 驅動的十二塊」：每塊宣告回答什麼、掛在哪個單位、誰寫、要看到什麼、沒有時印什麼；
再用七檔形狀不同的測試集量「填得滿」——一塊只有聯亞填得出來，就是 overfit。

## 1. 目標（使用者原話，依輪次）

- **10-05 之前**：「這個公司在做什麼、我們在賭什麼、為什麼卡在它」「需要一個總 status 一目了然的章節或圖表」「營收、股價、EPS 變化，backlog 有多少、放量會多大、
  會怎麼影響股價、怎麼被定價——不是一大串文字巴在我臉上」「會死嗎燈號看不懂」。
- **第一輪（v1–v3）**：「有因有果」「AI 成長多少、光通模組佔比、可能成長多少」「現在的營收成長是哪時候的單、未來的單能怎麼成長」
  「CPO 現在佔比？還是都是可插拔」「EPS 可以直接用術語」。
- **第二輪（v4）**：「喜歡 capex to 營收這條鏈路」「先把 app 長好，未來再濃縮成短文引言」「事件、現在營收來源比例、未來預估營收來源比例、量——才知道事件影響多大，
  不然無法判斷信心度」「四格方塊有點硬要變成圖表、沒資訊」「EPS、本益比、股價搭配事件的圖，真的看得出什麼嗎」。
- **第三輪（本輪）**：「訂一個 schema，避免過度 fit 聯亞」「可以大量用 LLM 讀圖思考研究回應，生成圖片也沒意見」
  「鏈的成長梯：AI capex 的變化、這間公司能吃到多少份額、同類公司變化——堆疊折線或更複雜的 UI」
  「鏈路要有技術描述：怎麼從 pluggable 到 CPO、CW 雷射在中間建立了什麼瓶頸、磊晶在 CPO system 多重要，著重物理或科技」「意見可能很分散，慢慢收斂」。

## 2. 現在的架構（個股頁怎麼長出來的）

- **三層**：短評（首屏，照五題排：v2 敘事七格、三題三個字、歸零燈、反證與加碼條件、是不是新賭注）／論證（六段封閉句型＋研究長文）／稽核（格）。
  ARCHITECTURE §6.11–6.12。「哪一格放哪一題」只有一份（`FIRST_SCREEN_QUESTIONS`），經 `.meta.json` 給 APP；APP 只讀，request path 不跑 LLM。
- **數字與文字分開**：數字由 authority 填 placeholder，文字由研究 session 寫進 append-only ledger。
- **資料有、頁面沒位置（本輪盤點，2026-10-05）**：Engine C 人工觀測已有 `customer_concentration` 31 檔、`segment_revenue_share` 32 檔、`backlog` 32 檔、
  `product_line_revenue_share` 8 檔、`company_guidance` 19 檔，個股頁沒有任何一塊在印。第一輪 v4 我說「挖到」的聯亞前四大客戶表，Engine C 早就有
  （`mo_086ed43cdb79e5ef3d9837aceae2186e`）——我沒先查自家庫（L11-4），也剛好證明了這件事。
  查證：`python -c "import sys;sys.path.insert(0,'.');from alpha.providers.three_questions import _open_readonly as o;c=o();print(c.execute('SELECT field_name,COUNT(DISTINCT ticker) FROM manual_observations GROUP BY field_name').fetchall())"`
- **路徑可以從結構表推**：`structure_table` 每列有公司坐的節點、需求錨、從錨走到這一層的鏈（`chain_names`）——需求傳導與技術鏈要畫哪幾層，不用手挑。

## 3. 歷史包袱（不能碰的邊界）

- **不排序、不出首選**（G1、L19）：同業一律固定順序。
- **財務只回答三個是非題、不長回估值模型**（G3）：B2／B3／B6 的財務內容全部掛在三題底下（出現在數字裡了嗎、已定價嗎）；不出目標價、合理價、bull／bear。
- **首屏的單位是句不是格**：首屏＝每塊一句讀法；圖與格在展開層。
- **A3 不落快取表、不當第二個 current-state authority**：研究 ledger 只存文字與引用，會變的數字由 A2 填。
- **APP 只讀；LLM 只在研究 session 改認知。** 「大量用 LLM」＝研究 session 多寫，不是 APP 或 daily 跑 LLM。
- **四個人工 gate 不因多一個畫面而放寬**：同階段同業若要進圖（新節點、新邊），照舊走 RA → pq2。

## 4. 局部最佳陷阱

1. **為聯亞手刻**：第一輪 v1–v4 每一塊都是看著聯亞的資料長出來的。換到 AXT（份額量不到、合約金額有揭露）、Sivers（押的那塊只占營收三成）就失效。
2. **層的知識寫在公司敘事裡**：每家各寫一次 CPO 是什麼，寫法不一致、過期時間不同。→ 掛在節點上寫一次。
3. **補格子過 filter（L19 的形狀）**：「填得滿」若變成目標，研究會去補格子。→ 填得滿表只當 overfit 偵測器；驗收另數圖、讀圖、敘事、registry 裡的東西；缺席是合法答案。
4. **份額變排名**：同業一旦依數字排序，就是跨檔全序。→ 固定順序。
5. **示意圖讀起來像事實**。→ 標「示意」、附出處；量化圖只畫系統裡的數字。
6. **研究量冒充進度**：層說明越寫越多，不代表頁面變好（「會隨我們多讀一份文件單調上升」的指標）。

## 5. Schema v0

### 5.1 單位（每塊、每個元素都要宣告掛在哪個單位）

| 單位 | 是什麼 | 誰的頁看得到 | 例 |
|---|---|---|---|
| 題材錨 | 題材宣告的需求序列 | 該題材的每一頁 | AI＝雲端四大資本支出 |
| 路徑 | 從錨走到公司坐的層（結構表 `chain_names`） | 走這條路的公司 | 光互連 → CPO → 外部光源 → CW 雷射 |
| 層／轉換 | 圖上的技術或材料節點；技術轉換（舊架構 → 新架構） | 坐這一層、或路徑經過它的公司 | CW DFB 雷射層；可插拔 → CPO |
| 插槽 | 某客戶產品裡的某一格 | 押這個插槽的公司 | Ayar SuperNova 的光源 |
| 公司 | 公司自己的事 | 這一頁 | 客戶結構、合約、財報 |
| 事件 | 一件帶日期的事 | 碰到它的公司 | 聯亞 08-26 長約 |

### 5.2 每一塊的合約欄位

`id`／標題／回答哪個問題／單位／要看到的元素（每個元素：要看到什麼、資料源類別〔機械／圖／研究／共識／市場〕、可用的證據等級、
**缺席時印什麼、在哪裡找過**、適用條件〔候選狀態、市場、在不在圖上〕）／一句讀法（研究寫；沒寫印「還沒寫」）／不准出現的東西／
**為什麼要這塊（使用者原話＋日期，防日後被刪）**／七檔填得滿（程式算）。

**證據等級不另造第二套**：圖上的內容沿用 `evidence_class`（owner：`query/origin_resolution.py`）；圖外的研究內容（層說明、讀法）用封閉字彙
「一手／學理／產業報告／推一步／共識／媒體／沒有」，S2 寫出它和 `evidence_class` 的對照表（L16）。

### 5.3 十二塊

| 塊 | 標題 | 回答 | 單位 | 誰寫 | 要看到什麼 |
|---|---|---|---|---|---|
| B0 | 頁首與一行狀態 | 這是誰、現在在哪 | 公司 | 機械 | 它是做什麼的一句、候選狀態、下次重看日；一行：最近營收年增・已定價百分位・結構判讀・會不會死 |
| B1 | 押什麼（三句話） | 五題① | 公司＋押的層／插槽 | 研究 | 它做什麼（實體產品、在系統哪一格、占營收多少）／我們賭什麼（押哪一層、要變大的是哪個量）／為什麼卡在它（量還是換不掉，附證據等級） |
| B2 | 需求傳導 | AI 的錢有沒有流到這一層 | 題材錨＋路徑＋層 | 機械＋研究 | 見 §5.4 |
| B3 | 營收從哪來 | 現在和之後的錢從哪來 | 公司 | 機械 | 產品、地區、客戶比例與變化／多出來的錢是誰付的／量（出貨、產能）／backlog 與長約（金額、期間、預付）／押的那一塊占營收多少／之後的比例（指引或判斷） |
| B4 | 技術鏈 | 這一層為什麼難、轉換時會變什麼 | 層＋轉換（跨公司共用） | 研究 | 見 §5.5 |
| B5 | 事件與影響多大 | 這件事該不該改變信心 | 事件 | 機械＋研究 | 碰到哪一塊營收、那一塊現在多大、事件多大（金額／量／期間）、何時進營收、共識有沒有動（沒有前值照寫）、相對同組的 1／5／20 日反應、讀法 |
| B6 | 怎麼被定價 | 五題②的脈絡（已定價嗎） | 公司 | 機械＋研究 | 一年市值＝營收 × 倍數拆解／EPS 實績與共識、本益比兩個年度／自家三年百分位與組中位／價格已經假設了什麼（一句） |
| B7 | 押對了夠大嗎 | 五題② | 公司 | 研究 | 翻倍要什麼為真（營收、出貨、產能、毛利到多少、何時）／加碼條件與狀態 |
| B8 | 錯了怎麼知道 | 五題③ | 公司＋讀圖 | 研究＋registry | 反證逐條、在盯或觸及、下一個裁決日 |
| B9 | 會不會死 | 五題④ | 公司 | 機械 | 四行白話（錢夠不夠、怕不怕還債、會不會一直增資、會計師有沒有警告），沒量到的照寫 |
| B10 | 是不是新賭注 | 五題⑤ | 公司 | 機械 | 和持股共用的需求錨與層 |
| B11 | 接下來看什麼 | 哪天要回來看 | 公司 | 機械＋registry | 法定期限、財報日、watch 到期、重看日 |

**適用條件**（v0 先寫兩條，磨合輪補）：B7 的加碼條件只對可開與已持有；B2／B4 對不在結構表的公司印「不在圖上」並指向走圖佇列。

### 5.4 B2 需求傳導（回應「鏈的成長梯」）

| 元素 | 要看到什麼 | 資料源 | 缺席 |
|---|---|---|---|
| 錨的變化 | 題材錨序列的季度值與年增 | A2：AI 題材＝雲端四大**現金**資本支出（SEC 季報，年初累計差分；**是代理**：含非 AI 支出、不含融資租賃）；第二條 NVIDIA 營收 | 題材沒宣告錨 |
| 路徑上各層 | 從錨到公司坐的層，每層一條年增 | 結構表的鏈＋該層同業序列 | 該層沒有同業序列（列名、寫原因） |
| 吃到多少 | 公司當季營收 ÷ 當季錨；往上＝吃到的比例變大 | A2；正式版換成美元（FX 序列） | 公司沒有營收序列（海外） |
| 份額（現在） | 「同階段同業」（賣同一種東西）的營收堆疊，本公司那塊標亮；覆蓋率必印（已知 N／M 家），沒數字的逐家寫原因 | 研究宣告同階段同業（或圖細化成更細的層）＋各家營收口徑（全公司／分部／量不到） | 同階段同業沒宣告；同業沒有數字 |
| 同層各家變化 | 最近一季年增，固定依名稱排，每家標階段；不同階段不比大小 | 結構表同層＋營收序列 | 該家沒有序列 |
| 份額之後怎麼變 | 為什麼會變（擴產、認證、客戶自製、技術轉換），每條連反證 | 研究（推一步） | 還沒寫 |
| 一句讀法 | 「錨 X、這一層 Y、它 Z，吃到的比例往哪走」 | 研究；數字 placeholder | 還沒寫 |

**圖上的需求錨節點對到哪條序列**（例：`Optical scale-up interconnect` → 雲端四大資本支出），用一張對照表宣告——字彙，日後加一列就能補（L2）。
**不准**：依數字排序同業、出首選、把份額寫成目標。

**第二輪畫布實測**（數字由 scratchpad 唯讀腳本從 Engine C 與 SEC companyfacts 算出，2026-10-05）：
- 錨：雲端四大資本支出 24Q1 443 億美元 → 26Q2 1,651 億美元，年增 +31% → +87%（加速）；光模組四家（COHR、LITE、AAOI、FN 總營收）年增 +0% → +51%。
- 聯亞：每 10 億美元 capex 換到的營收 24Q1 7.3 百萬元台幣 → 26Q2 7.4 百萬元（兩年持平，最低 24Q4 4.0，最近兩季回升）——成長大致跟著 capex 走。
- AXT：同一個比 51 萬美元 → 29 萬美元（兩年前的 56%）——還沒追上；AXT 10-K：2025-02-04 InP 基板列入中國出口管制、出口許可是它目前最大的挑戰。
  **同一個元素在兩檔說出不同的故事——schema 要的就是這個。**
- 份額：聯亞占台股三家磊晶廠（聯亞、英特磊、全新）營收 24% → 50%，但那不是 InP 磊晶市場。**真正的份額兩檔都量不到，原因不同**：
  聯亞是同階段同業沒宣告、IDM 自製沒數字；AXT 是同層七家只有它自己有基板營收（而且它自己也沒把 InP 拆出來）。

### 5.5 B4 技術鏈（回應「物理或科技」）

每一層、每一個技術轉換一份，**掛在節點上**，坐這一層或路徑經過它的每一頁引用同一份。

| 元素 | 要看到什麼 |
|---|---|
| 示意圖 | 從終端系統到這一層，光／電／熱怎麼走、這一層在哪裡（SVG，研究 session 寫，標「示意」、附出處） |
| 做什麼 | 物理功能，一兩句 |
| 為什麼難 | 物理、材料、製程、良率、可靠度、認證時間 |
| 轉換時需求怎麼變 | 量變多還是變少、規格怎麼變；現在走到哪一步（展示／認證／量產） |
| 瓶頸在哪一步形成 | 從材料到系統逐層：做什麼、為什麼難、圖上幾家 |
| 在系統裡多重要 | 換不換得掉、替代技術是什麼、什麼會讓瓶頸鬆掉 |
| 出處 | 每句附出處與證據等級；「學理」也要附一篇綜述或教科書 |

**寫在哪**：新的研究 ledger「層說明」——主鍵是節點或轉換 id（不是 ticker）、append-only、帶到期與重讀理由；那個節點的讀圖變 stale 時一起標。不 gate 任何東西。

**第二輪畫布實測（CPO 路徑）**：
- 由結構表推，這一份說明會被 28 家公司共用（坐 CW DFB 雷射、InP 基板，或鏈經過 CPO 的公司；其中兩家沒有代號、沒有個股頁）。
- 出處全部來自自家庫：NVIDIA 新聞稿 2025-03-18（雷射少 4 倍、電力效率 3.5 倍）、Broadcom 新聞稿 2025-10-08（可現場更換的 ELSFP 雷射模組）、
  Coherent 法說 FY26 Q2／Q3（scale-out CPO 營收 2026 下半年開始、scale-up 2027 下半年；scale-up 網路今天 100% 是電的）、Cignal AI 1Q26（Lumentum 最大一張 ELSFP 訂單、還沒量產）、
  AXT 10-K（2025-02-04 InP 基板列入出口管制）、聯亞年報（IDM 磊晶產能不夠而外包——供應商自述，弱）。學理三句（矽間接能隙、雷射怕熱、磊晶決定功率與壽命）出處待補。
- 寫出來的關鍵推論（推一步，待驗）：**CPO 不等於更多雷射**——scale-out 是替代（NVIDIA 說少 4 倍），scale-up 才是新增；對磊晶的意思是「少而強」。
  這句若成立，會改寫「CPO 放量＝聯亞放量」的直覺，正是使用者要的那種因果。

### 5.6 七條規則（schema 自己的不變式）

1. 技術和層的內容掛在圖的節點上，寫一次、同層每頁共用；公司頁只寫公司自己的事。
2. 每個元素都宣告「沒有的時候印什麼」，並寫出在哪裡找過（L11-5）。
3. 每改一次 schema，七檔測試集重算一次填得滿表；只有一檔填得出來的元素不上預設版面。
4. 同業一律固定順序（依名稱），不依任何數字排序、不出首選。
5. 數字由系統填（placeholder），研究文字不寫死會變的數字。
6. 示意圖附出處、標「示意」；量化圖只畫系統裡的數字。
7. 每塊一句讀法（研究寫），日後濃縮成短文引言；沒寫就印「還沒寫」。

## 7. 這輪盤點撞到的洞（真實資料）

1. **資料有、頁面沒位置**（§2）。
2. **層的粒度混了階段**：圖上「高功率 CW DFB 雷射」這一層 7 家裡有 IDM（Coherent、Lumentum）、磊晶（聯亞、全新）、晶片（華星光、Sivers）、代工（穩懋）——份額不能直接算；
   結構表裡沒有「InP 磊晶」這一層，聯亞掛在下一層。
3. **圖上的邊要回頭看**：IQE（主要做磊晶）、Coherent、Lumentum 掛在「InP 基板」這一層——是否對外賣基板要查。
4. **需求錨是圖節點、不是序列**；Sivers 的 Ayar 插槽，錨退回公司層、走 GlobalFoundries 到「成熟製程晶片」，跟它的 CPO 賭注對不上——結構表選錨的方式要回頭看
   （不在本 schema 的範圍；撞到第二次時進 failure log）。
5. **奇鋐不在結構表**：B2／B4 要有「不在圖上」的出口。
6. **只有光通訊一組**：Aehr、奇鋐、住友的事件相對反應要等「多主題等權組」。
7. **海外沒有營收序列**：Sivers、住友、JX、IQE——份額與同業變化只能部分（「海外財報來源」旁支）。
