# 盲點審查報告：以退休淨終值最大化為目標的槓桿 glide path

審查對象：把「回撤觸發才加碼」換成「依人生階段決定槓桿倍數」的構想，
在**資金來源不變、不新增 gate、不使系統複雜化**三個約束下。

已確立的前提（本輪實測與追源，不重推）見
[`../ROADMAP.md`](../ROADMAP.md) 的三則 2026-07-31 記錄。

---

## 最危險的三個盲點（先看這個）

1. 🔴 **硬上限只擋槓桿 ETF，完全不擋借款——而借款才是這個投組最大的槓桿槓桿。**
   `decision_lab/portfolio_risk.py:224-241` 的 `hard_blocks` 只會加入
   `etf_leverage_nominal_cap_reached` 與 `etf_leverage_effective_cap_reached` 兩種；
   `loan` 變數只在為 None 時發一個 `loan_leverage_unavailable` warning，
   **沒有任何門檻、沒有任何硬擋**。未動用額度 USD 185,793 ＝ NAV 的 46.1%。
   全額提款買 1x 標的，總曝險由約 1.0x 升到約 1.46x，而 `hard_blocks` 仍是空的、
   `槓桿 ETF 資金占比` 仍顯示 7.2%。**風控儀表板會顯示一切正常。**

2. 🔴 **naive 的「距離目標」glide path 在崩盤時會要求加槓桿——正是 2000-02 的死法。**
   若 target leverage = f(距離目標財富)，市場腰斬會使 NAV 減半、距離目標變遠，
   函數就會要求**提高**槓桿。這與本輪已驗證的反例（3x 淨值剩 0.05%）是同一個
   失敗模式，只是換成由公式驅動而非由情緒驅動。Ayres/Nalebuff 靠「上限 2x」
   把它壓住，但本專案目前沒有等價的總曝險上限（見盲點 1）。

3. 🟡 **「2x」的口徑被誤植：Ayres/Nalebuff 的分母是一生財富，不是現在的 NAV。**
   他們的核心論證是**未來儲蓄是一項尚未進場的類債券資產**；2x 是為了讓
   「目前金融資產」逼近「一生財富的目標股票配置」。若把它讀成「拿 NAV 的兩倍去投資」，
   就抽掉了整個理論基礎，只剩「加槓桿賺更多」——那不是他們證明的東西。

## 逐視角發現

### A1 證偽官

- [🔴] **觀察**：構想是「以 30 年後退休淨終值最大化為目標」，但**目標財富數字本身從未定義**。
  `config/beta_policy.json` 與 `Capital Authority` 都沒有 target wealth 欄位。
  **為何是盲點**：沒有目標就沒有「距離目標」，glide path 的自變數不存在，
  整個設計無法被證偽——任何槓桿水準都可以事後合理化。
  **修正**：先定 exact 目標數字與達成年份（例如「2056 年淨資產 USD N」），
  並寫進 `Capital Authority` 這個既有 authority，不新開檔。
  **怎麼驗證**：定義後，「現在該用多少槓桿」必須能由公式唯一算出；算不出就是還沒定義完。

### A2 反身性 / 已被定價

- [⚪] 此視角未發現重大盲點。glide path 不主張擁有 variant perception，
  它主張的是結構性配置錯誤（一生股票曝險過度集中後期），這不需要贏過市場共識。

### A5 敘事 vs 數字

- [🟡] **觀察**：構想引用 Ayres/Nalebuff「退休預期財富高 90%」，但那是
  **1871 年起的美股 + 2x margin** 的結果，不是「TQQQ + 台股槓桿 ETF」的結果。
  **為何是盲點**：把論文結論搬到不同工具上，等於假設工具無關——但本輪已證明
  3x 每日重設與 margin 的路徑性質完全不同（3x 可歸零，margin 會先被斷頭）。
  **修正**：若要引用該研究支持某個槓桿水準，必須用**同一種工具**重跑，
  或明確標註「工具已替換，論文結論不直接適用」。
  **怎麼驗證**：用真實 TQQQ（2010-02 起）而非模擬序列；跨 2000-02 的模擬一律不採信
  （本輪已踩過「除以趨近零價格」的假超額報酬）。

### B6 回測誠實官

- [🔴] **觀察**：本輪自己犯過的錯必須寫進設計約束——用「3× 日報酬」模擬跨越
  2000-02 得到 B/A = 724%，實為除以趨近零價格的假象。
  **為何是盲點**：任何未來要驗證 glide path 的回測，只要跨越 2000-02 或 2008，
  都會重蹈；而這類回測正是說服自己「可以再加一點槓桿」的最大來源。
  **修正**：把「跨越 2000-02／2008 的槓桿回測必須用真實基金資料，或明確建模清算與
  反分割」寫成 repo 層級的方法論約束（已記入 ROADMAP，但應在動工時升格為驗收條件）。
  **怎麼驗證**：任何回測若模擬淨值曾低於初始值的 1%，即判定該結果不可用。

- [🟡] **觀察**：本輪兩次回測都只有**單一路徑、單一起點**。
  **為何是盲點**：$1,000/月從 2010 開始，只是 30 年中的一段，且是最有利的一段。
  **修正**：若要據此調參數，至少做 rolling start（每個月當起點各跑一次）看分布，
  而不是看單一終值。
  **怎麼驗證**：若 rolling 分布的 5th percentile 為負，代表策略對起點高度敏感。

### B7 Regime 依賴

- [🔴] **觀察**：構想的兩個支柱都來自同一個 regime。本輪回測樣本（2010-02~2026-07）
  最大回撤僅 −35.1%；HFEA 也是 2010-2021 優異、2022 崩潰。
  **為何是盲點**：兩個「證據」其實是同一個十年多頭的兩種切法，不是獨立驗證。
  **修正**：設計時假設 30 年內**至少發生一次 −50% 以上的指數回撤**，並要求
  glide path 在那個情境下仍可存活（不被迫賣出、不歸零）。存活條件應是驗收項，不是備註。
  **怎麼驗證**：對 target leverage 做情境測試——指數 −50% 時，總曝險、
  已借款利息覆蓋、以及是否觸發任何被迫行為。

### B8 訊號落地縫隙

- [🟡] **觀察**：構想要取代「回撤觸發」，但沒說**新的加碼節奏由什麼決定**。
  現行 `signal_state` 的 tier／pace 是唯一的節奏來源；若 glide path 只給
  「目標槓桿倍數」，就缺少「今天該投多少」的橋。
  **為何是盲點**：會退回成人工判斷，等於沒有系統。
  **修正**（符合「重用既有機制」約束）：glide path 只決定 **target 曝險**，
  既有 `campaign_budget_fraction_by_sleeve` 決定**每輪投入速度**，
  既有 signal tier 降級為**只在多個候選間排序**（呼應 ROADMAP 已記錄的
  「gate 從『是否投入』改成『投給誰』」）。三者各司其職，不新增 gate。

### B9 風控 / 部位

- [🔴] **觀察**：見盲點 1。`hard_blocks` 的兩個成員都只看槓桿 ETF。
  **為何是盲點**：glide path 一旦允許動用借款，最大的曝險來源將完全落在硬擋之外。
  **修正**（最小改動）：新增**一個**硬擋——總曝險上限，分母是 NAV，
  分子＝非現金持股 ＋ 槓桿 ETF 的額外曝險 ＋ 已提款借款。這是**唯一必要的新 gate**，
  且它可以取代而非疊加現有兩個 ETF cap（ETF cap 成為總曝險的特例）。
  **怎麼驗證**：全額提款 USD 185,793 買 1x 標的時，系統必須顯示硬擋；
  目前不會。

- [🟡] **觀察**：3x ETF 與信用額度被當成同類槓桿，但**路徑性質相反**。
  3x：無斷頭、損失以投入額為限、但有每日重設耗損。
  30 年期利息按月付、到期還本的額度：**無斷頭、無每日重設耗損**，
  代價是利息現金流與到期本金。
  **為何是盲點**：對「30 年不被迫賣出」這個目標，額度的結構其實**優於** 3x ETF；
  若因為額度需人工 review 而預設走 TQQQ，是被流程便利性而非風險特性驅動。
  **修正**：把兩者的成本明確化後再選——額度的門檻是利率，3x 的門檻是波動耗損
  （已實測 QQQ 已實現波動 24–26%，對應 3x 年化耗損量級約 20%）。
  **利率若低於 3x 的耗損量級，額度在數學上更划算。**
  **怎麼驗證**：把 `Capital Authority` 的 exact 利率填入後直接比較兩個數字。

- [🟡] **觀察**：利息覆蓋沒有納入 glide path。AGENTS.md 已定「月息若需靠賣出 beta
  支付則該 tranche 不成立」，但那是人工判準，不在任何計算裡。
  **修正**：glide path 的可行解必須滿足「月息 ≤ 可支配現金流」，
  這個條件應與 target leverage 一起算，而不是事後檢查。

### C10 系統整合縫隙

- [🟡] **觀察**：目標財富、儲蓄率、退休年份都是**人生參數**，目前系統沒有存放它們的地方。
  `Capital Authority` 只有 `cash_floor` 與 `credit_facility` 兩種 record。
  **修正**（符合「不新增管道」約束）：在既有 `Capital Authority` 新增第三種 record
  `lifecycle_target`，欄位極簡：目標金額、目標年份、年儲蓄能力。
  不新開檔案、不新開 authority、沿用既有 readonly credential scope。

### C12 可操作性 / scope

- [🟡] **觀察**：使用者要求「不要太多 gate、避免複雜化」，但 glide path 本質上
  引入了三個新概念（目標財富、一生財富口徑、降槓桿規則）。
  **為何是盲點**：概念數量才是複雜度來源，不是 gate 數量。三個新概念即使只用一個 gate
  實作，理解成本仍然增加。
  **修正**：**最小可行版本只引入一個新概念**——「總曝險倍數」，
  並讓它同時扮演目標與上限。glide path 退化成一張手動維護的小表
  （例如：目前階段目標 1.5x，達成目標 50% 後降 1.25x，75% 後降 1.0x），
  存在 `Capital Authority`，由人在 pq2 決定何時換階段。
  **不建自動降槓桿引擎、不建 stress engine、不建新 signal。**
  **怎麼驗證**：實作後若程式碼新增超過約 150 行，代表 scope 已失控。

## 整體可證偽條件

這份構想的核心假設是：**在 30 年尺度上，提高總曝險倍數所增加的期望終值，
大於它在極端回撤中造成的永久損失。**

推翻它的觀測：
- 30 年內發生一次 −50% 以上指數回撤，且當時的總曝險使投組被迫賣出或利息無法覆蓋
- 借款利率上升至接近或超過股票長期期望報酬（額度為浮動利率時尤其）
- rolling-start 回測顯示 5th percentile 終值低於無槓桿基準

其中第一項是唯一會造成**不可回復**損失的，因此設計必須以它為主要約束，
而非以期望值最大化為唯一目標。

## 2026-07-31 補：利率 3.4% 填入後的工具比較（原優先序第 2 項，已解決）

同樣**每日重設維持固定倍數**、相同自有資本（2010-02~2026-07，16.5 年）：

| 工具與倍數 | 終值 | CAGR | 最大回撤 |
|---|---|---|---|
| TQQQ 實際 | $10,263,444 | 41.63% | −81.7% |
| 3.4% 額度維持 3x | $7,549,626 | 39.01% | −81.7% |
| 3.4% 額度維持 2x | $3,057,700 | 31.59% | −63.6% |
| 3.4% 額度維持 1.5x | $1,483,089 | 25.93% | −50.7% |
| 無槓桿 1x | $601,780 | 19.21% | −35.1% |

**三個推翻直覺的結論：**

1. **工具選擇是二階問題，倍數才是一階。** 額度 3x 與 TQQQ 3x 差 2.6pp CAGR，
   但 3x 與 2x 差 7.4pp、2x 與 1x 差 12.4pp。先決定倍數，再決定工具。

2. **歷史上 TQQQ 略勝，但那是零利率時代的產物。** 2010-2022 短率長期接近 0，
   TQQQ 的內部融資幾乎免費；本試算對額度收固定 (L−1)×3.4%。
   **若未來短率維持 4-5%，TQQQ 內部融資約 8-10% ＋ 內扣 0.84%，
   3.4% 固定利率的 30 年期額度會明顯較便宜。** 這是本專案的實際情境。

3. **一個早期比較曾誤導：** 若借款金額固定不變（不重設），市場上漲後槓桿會自然
   衰減到接近 1x，終值僅 TQQQ 的 0.15x。**「借錢買進然後放著」不等於「維持槓桿」**，
   兩者是完全不同的策略。要維持倍數就必須持續再借，這件事本身需要人工執行紀律。

**歸零門檻（決定性）：** 維持 L 倍時，指數下跌 100/L% 即自有資本歸零。
3x → 33%、2x → 50%、1.5x → 67%。QQQ 在 2022 曾跌 35.1%、2000-02 跌 83%。
**維持 3x 的歸零門檻低於已經發生過的回撤。** TQQQ 在 2022 未歸零（−81.7%）
是路徑運氣而非設計保障。

## 接下來盯什麼（按優先序）

1. **先補總曝險硬擋**（唯一必要的新 gate）。在動任何 glide path 之前，
   目前 USD 185,793 的額度完全不受硬擋約束就是敞口。
2. ~~填入 exact 借款利率~~ — **已完成（3.4%）**，見上節。結論：先決定倍數再選工具；
   在非零利率環境下 3.4% 固定額度較 TQQQ 便宜，但差距遠小於倍數本身的影響。
3. **定義 exact 目標財富與年份**，寫進 `Capital Authority` 的新 record type。
   沒有這個就沒有 glide path。
4. **手動階段表先行**：用一張三階段的小表跑三到六個月，觀察是否真的需要自動化。
5. **rolling-start 回測**驗證分布而非單一路徑；任何跨 2000-02 的模擬一律不採信。

## 明確不做

- 不新增資金管道（維持 `Portfolio CASH − cash floor` ＋ 既有 credit facility）
- 不建自動降槓桿引擎、debt optimizer、通用 stress engine
- 不把 SOXL 或其他新槓桿工具加入 universe（本輪已確認波動耗損不利）
- 不讓任何自動機制執行提款；exact draw／instrument／tranche 仍是 pq2 人工核准
