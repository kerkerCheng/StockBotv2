## 4. 「九成」怎麼量

- 每檔照清單寫完、他讀完之後，把他問的每一句記進漏題帳，分成**清單外**（不屬於任何一題的子題）與**題內**（有那一題但沒答好）。
- 九成＝清單外 ≤ 1 條。連續兩檔做到，清單才算夠用。
- 清單外的每一條當場收進清單，並回頭補到已發布的頁。
- 這是機制的量測，不算研究進展。研究進展照 ROADMAP 那一列：數寫回現行敘事的檔數與由此登記的等待。

- 2026-11-25 晚加第三類**寫法**（講的是讀起來怎樣：讀不懂、太長、讀錯意思）：不計入九成，但每一條都要變成 skill 的一條規則或
  交稿前核對的一行。分類是執行者判的，他可以改判。

現在的成績：亞泰（v1）清單外 4 條、題內 2 條——不到。Aehr（v2）清單外 1 條、題內 1 條、寫法 2 條——照執行者的分類剛好到；
「哪一邊會贏」那一句若改判清單外就是 2 條、不到。v3 還沒在新的一檔上試過。

## 6. 不變的

- 故事頁是研究判斷的呈現，不是 authority。不入圖、不改候選狀態、不給目標價、不跨檔排序；價格只當脈絡。
- 現行敘事、候選板、APP 個股頁照舊；故事頁不取代它們（S4 才談）。
- 四個人工 gate 不動。付費來源要他點頭。讀完後的選擇照「記錄看了沒買」記。
- 未量測的讀法（四格、市場知道了嗎）不當篩選條件、不排序。

### 8.2 分工（S4a）

- **偵探＝蒐證＋拼線索。** stock-story 的蒐證順序搬過去當前半：自家庫（含這一檔的個股頁物化檔）、公司一手、買方端、對手端、
  技術文件、媒體。對外抓取由主 session 做（不帶信箱與專案名），新讀的一手存節錄，圖的洞登記成線索。後半照舊：線索包 →
  唯讀子代理拼線索 → 主 session 核引文。產出多一份蒐證包：十二題各有哪些證據、哪些查不到。偵探照舊不看價格。
- **stock-story＝呈現。** 問題清單、寫法規則、交稿前核對、頁尾四節、讀後記帳；輸入是蒐證包。股價與「市場知道了嗎」的反應表
  在蒐證包定稿之後才抓，看過誰的價格寫在頁上。
- 付費來源、四個人工關卡、「不給目標價與排序」都不變。

### 8.3 自我檢查（S4b）

1. **機械檢查**（零 token，交稿前跑）：量看得到的字數；頁首有沒有指到別檔或後面的節；同一個數字出現幾次；有兩家公司名字的句子裡的
   「它」；引號裡的字串在出處檔找不找得到；頁上寫「已登記」的對等待日曆；系統的詞有沒有直接上頁。
2. **冷讀**（每頁一次、便宜模型、唯讀）：乾淨 context 的讀者只拿到頁面的文字，不給清單、不給對話。回五樣：五句話重述這家公司在賭什麼；
   第一次出現時沒解釋的詞；要回頭重讀的句子；讀完還想問的（最多五個）；覺得重複的。主 session 拿重述對頁首（重述錯的地方就是會被讀錯的地方），
   拿「還想問的」對清單（清單外的就是漏題的預報）。讀者不查資料、不給投資建議、不寫任何東西。
3. **回測**（先量測後信任，INV-5）：把他已經讀過的舊版交給冷讀——Aehr 第 1 版、Sivers 第 8 版、亞泰他第一次讀的那一版——
   看它抓不抓得到他實際說過的話（Aehr 三句、Sivers 一句、亞泰六句）。抓到幾條記進漏題帳；某一類抓不到，冷讀就不拿來擋那一類。
4. 漏題帳每一列加一欄「冷讀先抓到了嗎」。冷讀留不留，看這一欄的數字。

### 8.4 進 APP（S4c）的方向（細節等 plan）

- 故事正文由研究 session 寫、分版存在私有區；APP 個股頁有故事就顯示故事，沒有就照舊顯示現在的個股頁（現在只有三檔有故事）。
- 「系統裡的它」那一節由程式照物化檔填，不手抄。
- request path 照舊：不跑 LLM、不抓外部資料、不寫任何東西。
- 要他簽的：`AGENTS.md` 講 APP 的兩句（首屏三層；日期留在依據）怎麼改；查核用的格子哪些從畫面拿掉；層的數字帳要不要加。

### 9.2 定案的分工

- **一句「做深 <代號>」串起兩段。** 個股頁上的按鈕複製的就是這一句加這一檔的現況。
- **偵探**（`skills/detective`）：外勤蒐證（主 session 對外抓；自家庫 → 公司一手 → 買方端 → 對手端 → 技術文件 → 媒體）→
  內勤拼線索（線索包 → 唯讀強模型子代理 → 主 session 核引文）→ **落帳**（新讀的文件存節錄、圖的洞登記成線索、敘事換版、
  把「夢醒」與「再一次要看的」登記成等待）→ 蒐證包（十二題逐題的證據索引、查不到的、圖的洞）。全程不看股價。
- **故事頁**（`skills/stock-story`）：拿蒐證包 → 先分類 → 蒐證包定稿之後才抓股價 → 寫 → 機械檢查 → 冷讀 → 自評 → 存進 APP → 讀後記帳。
- 問題清單是兩份 skill 共用的契約：偵探照它蒐證，故事頁照它寫。只說「偵探 <代號>」＝只做內勤，照舊。
- 長的故事頁不進 research-drain 自動跑，由使用者點名。敘事換版之後故事頁要「對版」——對過新舊兩版，頁上講的沒變就重綁到新版，
  變了才小修；這是 drain 做得完的小事，所以待做清單有它一格。
- 故事頁由強模型照 skill 寫，沒有機械化的初版：機械的部分是檢查，不是寫。

### 9.3 進 APP 的形狀（執行者定的；細節在 plan）

- 故事頁＝一段 HTML 片段＋一份宣告（照哪一版敘事寫、故事押在圖上哪幾個節點、頁上寫的每一條等待對到哪一筆登記、自評）。
  存在私有區、只能追加、一版對一版敘事。
- 片段只准白名單裡的標籤與屬性，樣式只用 repo 裡的樣式表（APP 的安全標頭本來就擋行內樣式與行內程式）。寫入時檢查一次，物化時再檢查一次。
- 「系統裡的它」不手抄：故事頁留一個空位，APP 用個股頁物化檔填——候選狀態、押的層與路徑、讀圖、四盞燈、三題、已登記的等待、現在的股價。
- 故事和系統對不上的三種算得出來：敘事換版了、頁上寫了但沒登記的等待、故事押的節點和敘事押的不同。進待做清單一格。
- 沒做深的檔：短故事（現有的那本帳）＋系統示意圖＋「系統裡的它」＋「做深這一檔」。舊版個股頁過渡期留一個連結。
