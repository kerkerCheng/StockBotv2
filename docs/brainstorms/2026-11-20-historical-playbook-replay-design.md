## 1. 目標

消化端有三個缺口，本開發只先處理打底的那一個：

| 缺口 | 使用者的話 | 本開發處理到哪 |
|---|---|---|
| ①賭注說不成一句 | 「未來要發生什麼才能有倍率」 | 後段（§6 第 4 段），要先有 ②③ 的結果 |
| ②沒有時間感 | 「timing 這個維度」 | **劇本**：一段需求灌進一層時，事件照什麼順序出現、各段多久、怎麼結束 |
| ③挑不出來 | 「沒辦法從三四十檔挑出幾個」 | **先量**：圖上哪個結構特徵在樣本外分得出「層裡誰吃到」——量得出來的才有資格當預設的依據 |

**一句話：把「一層薄的供應商被集中需求擠壓」的歷史案例，用同一套 schema、同一個 as-of 規則重建成帶日期的事實序列，
機械算特徵，對封存的報酬做預先登記的判讀。只回放事實，不回放判讀。**

## 4. 局部最佳陷阱（明確不做）

1. **第五次全市場財務條件**——同一題。全市場月營收只當分母（同期基準率）。
2. **讓模型回頭寫讀圖或敘事**——記得結果。模型在本稿只准做一件事：把文件裡寫的字抽成帶日期的 schema 事實。
3. **只收贏家**——只有召回沒有精確。整層成員全收、沒擠成的段也收。
4. **把歷史的邊灌進正式的圖**——幾百包入圖 gate、舊邊觸發屬性衝突佇列、污染走圖與讀圖 staleness。
5. **看到結果再定特徵或判讀線**——特徵定義、判讀線先 commit；報酬封存到特徵凍結之後才開。
6. **規模先行**——先兩段試點量成本與產出率，再報二十段的規模。

## 5. 提議的架構

### 5.1 一條線五段，LLM 只在第三段

```
①規則選案（機械）→ ②規則選文＋抓檔（機械）→ ③逐字抽取（LLM，零工具）→ ④as-of 特徵（機械）→ ⑤對封存報酬判讀（預先登記）
                                               └→ 隨機抽查核引文（量核出率）
```

### 5.2 回放語料：長期維護、不是 authority

- **位置**：原始檔 `library/replay/raw/`、抽取結果 `library/replay/extractions/`、劇本登記表 `library/replay/episodes.jsonl`
  （哪一段、節點、層成員、起點、選案與選文規則版本、文件清單與抓不到的計數）。程式放獨立套件 `replay/`。
- **性質**：公開文件重抓得回來（L10：今天重取一次拿得回來 → 可重建），所以它是可重建的評估語料，不是 append-only authority；原始檔留底是為了省重抓與防來源下架。
  repo 公開：只收公開申報與公司自己公開的簡報；券商、付費新聞不進。
- **與正式圖的關係：單向晉升。** 語料裡某條事實對現在的敘事有用 → 當一般來源走既有入圖包、使用者 `go`。不混查、不反向。
  **防呆做成測試**：正式路徑（`query/`、`alpha/`、`webapp/`、`crons/`、`engine_b/`）不得 import `replay`（import 邊界測試；失敗不可能發生，不靠自律）。
- **身分**：公司一律用 `config/company_identity.json` 的 `co:*`（INV-1：ticker 不是身分）。名冊沒有的舊公司要補——補名冊照既有規矩走 pq2，一段鑄一個號、packet 列全部要補的公司。
- **維護成本**：歷史不變，一段一段加，沒有每日成本。現行題材不進語料（它本來就在正式圖）。
- **之後的用途**：新假說不必重抓；新候選找參考類；同一層的上一輪餵現在的層說明；偵探與讀圖的校準題庫。

### 5.3 選案規則（劇本偵測）

- **細產業**＝櫃買產業價值鏈平台的節點（機械、公開、可重抓）。已知限制：名單是今天的版本（當年已下市的公司會漏，要另由歷史月營收頁補並數出來）；
  節點可能比一層粗（「硬板・軟板・IC 載板製造」是一個節點）→ 節點內再用**年報產品別營收比重**分（規則：該產品線占營收 ≥ 某比例才算層成員；比例待審查定，定了不改）。
- **一段**＝同一節點在 6 個月窗內 ≥ 3 家出現 H11 定義的量的拐點（連三個月營收年增 > 40%，逐字沿用）；起點＝第一家的事件月月底。
  偵測到的段**全部登記**，不看報酬。
- **擠成／沒擠成**（只用來標型別，不用來選）：起點後 24 個月，層成員等權籃子對全市場等權的超額 ≥ 門檻＝擠成（門檻待審查定）。
- **試點的兩段**：成功段＝**ABF 載板 2020–2022**（使用者 2026-11-20 點名；理由：schema 六種事件都有、有清楚的結束、同一層現在就在正式圖上——
  名冊已有欣興、南電、景碩、Ibiden、日東紡）；失敗段＝偵測清單裡標「沒擠成」、`sha256(節點|起點)` 最小的一段。
  **ABF 是點名不是機械選的 → 試點的結果只驗機制，不進任何判讀線**（§7 J5）。

### 5.4 選文規則

- **對象**：層成員全部；加上它們年報「主要銷貨客戶」「主要進貨廠商」段具名、且名冊有或補得進名冊的對手方。
  年報寫「甲客戶」解不出來的：數出來，不猜。
- **海外同業（J6，使用者定案：直接 web search）**：對象＝層成員年報競爭者段具名、或被 ≥ 2 家層成員的文件點名為同層供應者的海外公司（機械）。
  沒有現成抓檔路線的，在**互動 session** 用 WebSearch 找它自己公開的法說簡報與年報，規則先寫死：
  ①查詢字串用固定模板（公司英文名＋文件型別＋年；年＝窗內每一年），不臨場改寫；②只收公司自己網域或交易所公告系統上的文件；
  ③URL 必須出現在該次搜尋結果裡（沿用新聞雷達擋編造網址的規則）；④發布日必須寫在文件或頁面上，推不出就排除並計數；
  ⑤每家每年有上限；⑥查詢字串、命中清單、收了哪幾份、每份沒收的理由，全部寫進劇本登記表。WebSearch 不進任何無人值守流程。
- **型別與窗**：起點前 18 個月到後 24 個月的年報、法說簡報、歷史重訊、財報附註（合約負債、重大承諾事項）；美股 10-K／10-Q／8-K＋EX-99。
- **照規則抓、不手挑**；每家每型別有上限（新到舊）；抓不到的逐家逐型別計數（INV-3：每個 filter 報得出 input／accepted／filtered／reasons）。
- **大檔節選**：年報只取章節白名單（營運概況、產業概況、主要客戶與供應商、長期契約、資本支出計畫），白名單先定、不看內容調。

### 5.5 抽取

- **沿用** `extract.py --scaffold` 的提示、`--response` 的後處理（doc_id 前綴、schema 版本）與 `loader/validate.py`。逐字引文規則照舊：具體公司名、型號必須在 quote 裡。
- **多一張事件表（只在回放語料）**：正式 schema 把擴產、漲價這類時變事實存成自由文字的 dated Claim，客戶資本承諾沒有結構化欄位——機械算不了。
  回放語料的抽取輸出多一個 `events[]`，封閉字彙：`capacity_announcement`（誰、多少、預定開出日）、`price_change`（方向、幅度）、
  `capital_commitment`（誰付、付給誰、形式：預付／長約／共同投資）、`second_source`（哪個客戶、新增誰）。每筆必帶逐字引文與來源。**正式 schema 不動**；
  這張表之後要不要回到正式那邊，是另一個決定（真實資料撞上去才知道表長什麼樣，L6）。
- **`published_at` 必填**；推不出日期的排除並計數（與 as-of 函式同一條規則；不得用抓取日冒充）。
- **執行者**（§7 J2）：建議 `claude -p` 零工具批次（沿用 `crons/llm_step.py` 的呼叫形狀：程式組提示 → 模型回 JSON → 程式後處理與驗證 → 程式寫檔）。
  沒有工具就沒有沙盒要證明；模型不寫任何檔。
- **抽查**：按公司分層隨機抽，逐條核引文在原文裡逐字存在、日期與主受詞正確。核出率低於門檻就停（門檻待審查定）。抽查時不知道誰贏誰輸（報酬還封存）。

### 5.6 特徵（每個 schema 欄位怎麼變成一個數；as-of T＝段的起點）

| # | 特徵 | 定義（只用發布日 ≤ T 的事實） | 來源 |
|---|---|---|---|
| F1 | 客戶端或第三方印證 | 指向這家的 `supplies_to` 邊裡，`origin_entity` 不是它自己、也不是關係人的邊數 | 邊＋sources |
| F2 | 合格狀態 | 它所有供應邊裡 `qualification_status` 的最高等級，與首次達 qualified 的日期 | 邊屬性 |
| F3 | 層的供給側家數 | 被任何文件點名為這個 component 供應者的公司數 | 邊 |
| F4 | 客戶掏錢 | 以它為收款方的 `capital_commitment` 事件數 | 事件表 |
| F5 | 供給時鐘 | 同層已宣布、尚未到預定開出日的 `capacity_announcement`：家數、最早開出日 | 事件表 |
| F6 | 第二來源 | 它所在的客戶插槽是否已出現 `second_source` | 事件表 |
| F7 | 上游單一來源 | 它 `depends_on` 的上游層是否有非自報的 `sole_source` | 邊屬性＋sources |
| 對照 | 量的拐點、合約負債占營收 | 逐字沿用 H11；財報附註 | 月營收、財報 |

特徵定義在看任何報酬之前凍結；「算不出」是合法值，逐家計數。

### 5.7 結果變數與封存

起點後 12／24 個月：曾達 2 倍（月底收盤）、等權超額（對全市場、對節點籃子各一）、6 個月內先跌 30%；另記股價高點日、毛利率高點日、第一個與第二個同層擴產宣布日。
價格用還原月線；封存檔照偵探回溯的做法只印案例編號，特徵凍結 commit 之後才開。

### 5.8 假說與判讀線（草稿——要審查者攻擊；試點不判）

判讀總則沿用 2026-11-01 追加（曾達 2 倍比例、等權平均超額、單檔最大貢獻；另印先跌 30%）。每條都要有 n 門檻與「不足」出口。

- **HP1 客戶掏錢**：同層內，T 時 F4 > 0 的供應商，曾達 2 倍比例與等權超額都高於 F4 = 0 的。（Phase 7 的 H10）
- **HP2 客戶端印證**：同層內，F1 > 0 對 F1 = 0，同上兩量。（H3）
- **HP3 層薄**：段的層級——F3 小的段，節點籃子 24 個月超額高於 F3 大的段。
- **HP4 第二來源**：F6 事件之後 6 個月，原供應商對節點籃子的超額為負的比例過半。（H4）
- **HP5 供給時鐘（只描述、不判）**：股價高點相對「第二家同層擴產宣布日」與「毛利率高點日」落在哪。

**架構邊界**
