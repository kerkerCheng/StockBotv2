## 1. 起因與使用者原話（2026-11-24，同一段對話，依序）

- 「之前兩次回測（H17、H18）我都沒感覺到切題」——H17 從「股價已經漲一倍」出發，答的是大漲之後會怎樣；H18 受限於資料，量的是「單一公司被媒體寫漲價缺貨、公司出來澄清之後」。
  劇本的單位是層、要有買家那一端。「問題在登記前就被資料悄悄換掉了。」兩次只排除了兩條路（用股價定義走得快的後來崩得更多；公開的單一公司好消息跟隨便挑一檔差不多），都沒回答劇本對不對。
- 這個 Phase 為什麼存在：「我現在看到的東西都沒有讓我真的有信心去下任何賭注」「我們要有劇本樣本多，我們才好說現在是走哪一個劇本」「符合劇本但沒漲的……不然盲點很大」
  「我要找的是浪潮中走的快的」「回放可以，但要切題」。
- 要知道的四件事：「眼前這一檔像哪一段舊劇本、走到第幾個月、接下來應該看到什麼、看到什麼代表這次不一樣該認錯。」
  做成的樣子「不是卡片或回測變多，而是可開的檔寫了對照讀法，並由對照讀法登記出反證與前向假說」。
- 劇本與脈絡：「把我們整個系統放回當時，像現在一樣每天做研究。當時會判『可開』的，加上當時抓得到的額外脈絡，組合起來，最後真的漲起來的，就是劇本。我們要找的是那個『脈絡』的位子。」
  兩個修正：要連沒漲的一起看（只看贏家會找到兩邊都有的東西）；「可開」本身也要被量（沒有比隨便挑多漲，脈絡就在更前面：層選錯了）。
- 事後諸葛是硬限制：規則在看資料前寫死、照規則抽出全部、不挑；回放裡模型只准逐字抽取、不准判讀，判讀類的只能前向；每個回溯量測寫出事後知識可能從哪裡漏進來。
- 「都照建議，先做2023-2026的早期AI吧 我覺得光這一段就做不完了，畢竟我們做的要蠻深的？」
- 「這樣可以 只是我覺得確實跟你擔心的一樣 由買家點名真的缺或啥的 好像不多嗎？ 瓶頸感覺都是要讀圖或是偵探挖個一兩層比較容易拿到？ 純讀文件可以嗎」
- 「可以簽 但你要怎麼實現讀文件來找兩手這件事？」

## 2. 定案

| # | 決定 | 怎麼定的 |
|---|---|---|
| D1 | **成品＝帶分母的對照表，再接到每檔可開的對照讀法**；不追求「劇本對不對」的判決（一波的層數有限又同漲同跌，判決多半又是不確定） | 「都照建議」 |
| D2 | **單位是層；每層有自己的第 0 月**＝買家端第一次出手（說缺或拿錢綁產能，先到的算），不挑單一起點月。沒有買家端事實的層沒有第 0 月，留在分母 | 「都照建議」；後半是同日修正（§3 新觀察④） |
| D3 | **買家端＝雲端四大＋NVIDIA，加它們的文件逐字點名的供應商（一手）**。Oracle、CoreWeave 是 2026-10 才進需求錨的，回放不用 | 「都照建議」 |
| D4 | **範圍只做 AI 這一波，2023 起**；第二波（非 AI 的舊浪潮）看完第 4 步再決定 | 「先做2023-2026的早期AI吧」 |
| D5 | **層的名字用當時文件的詞、成員只認當時以前的文件；今天的圖不拿來認層與成員**（它只在名單凍結後當對照：當年這個詞是今天哪個節點）。專用 Neo4j 先不建，做到逐字供應關係那一層再議 | 「第三版可以不算數……照你建議吧」 |
| D6 | **層的名單＝從錨照文件裡的點名關係往上走兩手，碰到的層全收**。「買家說缺」「供應商自己說缺」「買家拿錢綁產能」「只有幾家做」四種記號當欄位各自量，**不當入選條件** | 「這樣可以……純讀文件可以嗎」→「可以簽」 |
| D7 | **先考試再回放**：拿今天讀過的層當考卷，看寫死的記號規則分不分得出讀圖判「量／換不掉」與「都不是」的層；不碰股價。分不出就不回放，這個 Phase 改成只做前向 | 「可以簽」 |
| D8 | **切題三條**：每個量測提出時先用一句話寫它回答使用者哪一句話；資料逼著換題時明講「因為資料，這次量的是 X，不是你問的 Y」，由使用者決定做不做；報告第一段寫「它不是什麼」 | 使用者第一則的「規則」 |
| D9 | **邊界**：找到的脈絡只能變成對照讀法、前向假說或 watch，不得變成門檻、排序、首選或部位大小；判讀線先登記、一次判讀、不改門檻重跑 | 使用者第一則 §6 |

回放是**寬而淺**：全收、只有抄得到的東西；問到哪做到哪。使用者問「做的要蠻深的？」——要切題就得重建結構裡抄得到的那一半（誰供誰、幾家做、誰預付），判讀那一半仍然不回放。

## 4. 回放要回答的四題

| 題 | 問句 | 對到使用者哪一句 |
|---|---|---|
| 甲 層選對了沒 | 從錨走得到的所有層裡，帶哪一種記號的層，裡面的小公司翻倍比較多？ | 「我要找的是浪潮中走的快的」 |
| 乙 分母 | 記號都有、卻沒漲的有幾層、幾家、長什麼樣？ | 「符合劇本但沒漲的……不然盲點很大」 |
| 丙 刻度 | 漲的那些從第 0 月起，第幾個月出現什麼、第幾個月翻倍；穩不穩到能說「現在第幾個月」？ | 「我們要有劇本樣本多，我們才好說現在是走哪一個劇本」 |
| 丁 分岔 | 漲的與沒漲的是事前就不同，還是某個月才分開、分開前先出現什麼（反證的來源）？ | 「我現在看到的東西都沒有讓我真的有信心去下任何賭注」 |

**它不是什麼**：不是劇本對不對的判決（只有一波）；不是真的「可開」（判讀回溯不乾淨，回放裡只有抄得到的記號）；不是把整個系統放回去（X 上的 lead 與讀圖判讀放不回去）；
不測「會不會選到 AI」（選這一波與錨本身就是事後知識，使用者已接受全押 AI）；不告訴使用者層裡挑哪一家、買多少。

## 5. 步驟與停點

| 步 | 做什麼 | 停點 |
|---|---|---|
| 1a | 記號規則（四種記號各自的寫死定義）與考試規格（考卷、計分、及格線） | **使用者簽** |
| 考試 | 用今天的圖與庫跑一次，不碰股價；一次計分 | 不及格 → 回放停，使用者決定 Phase 是否改成只做前向 |
| 1b | 回放規則規格，看資料前寫死：買家端名單與文件型別、兩手怎麼走、成員認法、「小」的門檻、結果與對照組 | **使用者簽**（考過才寫） |
| 2 | 建名單，不碰股價：文件 → 逐字句 → 層 → 成員；全收、逐項計數 | — |
| 3 | 切題回報：幾層幾家、哪裡被資料換了題 | **使用者說做才往下** |
| 4 | 登記判讀線 → 階段一 digest → 假結果自查 → 接股價、一次判讀 → 獨立覆核（照 H18 的流程） | 判讀線登記前要使用者選的題目先問 |
| 5 | 甲成立：補成員的帶日期事件與數字（丙、丁；描述型、輸家同列）。甲「沒差」：改用「錢先到」（層內營收先轉強）定義層，另登記 | — |
| 6 | 同一把尺接到今天：每檔可開寫對照讀法，每句「接下來該看到」登記成有到期的反證或前向假說 | 驗收只數這一步 |

**只能前向的**：真的「可開」有沒有比隨便挑多漲；對照讀法準不準（每句「N 個月內該看到 X」到期對答案，一兩季就有回饋，不必等翻倍）；回放找到的差異有沒有用；使用者的進／不要／等。

## 6. 事後知識從哪裡漏、各用什麼擋

| 漏點 | 擋法 |
|---|---|
| 後來才發表的文件 | as-of：每條事實帶文件發布日，查詢必帶時點；推不出日期的排除並計數 |
| 清單是誰挑的（今天的圖有哪些層與公司，是知道結果之後挑的） | 照規則全收；不讀今天的圖、名冊別名、劇本卡的名單 |
| 讀的人（模型知道結局） | 只准逐字：三格的字都要出現在引文裡、關係與記號用封閉字彙與寫死的詞表、引文程式全檢；沒有任何一步問它「算不算瓶頸」 |
| 寫規則的人（知道 2023–24 誰說了什麼、誰漲了） | 規則看資料前寫死、使用者簽、簽了不改；名單凍結後才接股價；兩階段登記、假結果自查、獨立覆核 |
| 今天的名單與市值是倖存者 | 含下市的交易所月底行情、當時的市值 |
| 選這一波與錨本身 | 不擋，明寫：它不測「會不會選到 AI」 |

## 7. 兩手怎麼走（實作草案；細節在 1b 定案）

**抄什麼**——三種句子，每一句都帶逐字引文與文件發布日：

| 句型 | 例（NVIDIA 2023-02-24 年報） | 變成什麼 |
|---|---|---|
| 買方自己寫的供應句 | "We purchase substrates from Ibiden Co. Ltd., Kinsus Interconnect Technology Corporation, and Unimicron Technology Corporation, and memory from Micron Technology, Samsung Semiconductor, Inc., or Samsung, and SK Hynix." | 賣方 → 買方，零件＝substrates／memory |
| 賣方自己寫的客戶句 | （賣方年報寫某某是客戶、占營收幾成） | 同一種關係，來源標「賣方自報」 |
| 不具名的依賴句 | "limited number and geographic concentration of global suppliers, foundries, contract manufacturers, assembly and test providers, and memory manufacturers" | 那個零件的「只有幾家做」記號 |

**怎麼找到文件**——兩個方向：
- **往下讀**：錨與第一手公司自己的年報（一年一份），抄出它點名的供應商與零件。
- **往上找**：全文搜尋「誰的文件提到這個名字」，命中的段落抄句子。美股與在美掛牌的走 EDGAR 全文搜尋（2001 年起、可限日期；`library/private/replay_cards/fts.py`）。
- 第一手＝錨的文件點名的公司，加上文件裡把錨寫成客戶的公司；第二手＝對每一家第一手公司再做一次。走到的公司與零件全部記下來，as-of 就是照文件發布日濾。

**模型做什麼、程式做什麼**：模型只把含有名字的那一段裡的句子照抄出來，填買方、賣方、零件三格（三格的字都必須出現在句子裡），關係從封閉字彙選（供貨／競爭／其他）。
程式核引文逐字存在、三格是引文的子字串、日期來自申報系統。「競爭」「其他」照數、不成邊（INV-3：每個 filter 報得出 input／accepted／filtered／reasons）。
人抽樣核精確率與召回率，核的時候股價還沒接上。**層＝零件那一格的字**；同義詞合併表在接股價之前定、逐筆留紀錄。

**真的走一次（2026-11-24，只讀）**：
- NVIDIA 2023-02-24 年報的一段點名 **18 家、六類零件**：晶圓（TSMC、Samsung）、封裝測試（Amkor、BYD Auto、Hon Hai、King Yuan、Omni Logistics、Siliconware、Wistron）、
  介面卡與交換器系統（Flex、Jabil、Universal Scientific Industrial）、網路線（Fabrinet）、載板（Ibiden、Kinsus、Unimicron）、記憶體（Micron、Samsung、SK Hynix）。
- 一年後（2024-02-21 年報）同一段多了一句 "We utilize CoWoS technology for semiconductor packaging."，組裝測試的名單換成 Hon Hai、Wistron、Fabrinet——**新出現的名字本身就是一條帶日期的事實**。
- 四家雲端買家的年報幾乎不點名供應商（2022–2023 年度 8 份裡 7 份 0 行）：實際上是從 NVIDIA 起步。
- 往上找的規模（EDGAR 全文搜尋，2022-03-01～2023-02-28 申報的 10-K 與 20-F）：提到 NVIDIA 的 83 份（含它自己同一次申報的多份文件）、Taiwan Semiconductor Manufacturing 65、Wistron 18、Fabrinet 12、Unimicron 5。是幾百份的量，不是幾萬份。
  提到的公司有客戶、對手、供應商、夥伴，要讀句子才分得出來——這就是模型逐字抄的那一步。

**已知會弱的地方**（1b 之前先講）：
1. 台日韓的小公司不向美國申報；台股年報沒有全文搜尋（手上全市場帶日期的文字只有重大訊息）。往上找在最需要的地方最弱。
2. 台股年報的主要客戶多半匿名（甲客戶），抄不到的照數、不猜。
3. 大樞紐（台積電）會把名單炸開：往上找只認句子裡寫出買賣關係的，先數再定上限。
4. 模型分「供貨／競爭／其他」是輕度的判斷，要靠抽樣核與封閉字彙壓住；核出率低於門檻就停。

## 9. 不變的

- 描述型的發現要變成依據，只有前向假說與 watch 兩條路；不得直接變成排序、門檻或預設。
- 回放的資料不是 authority、不被正式路徑讀；要用在現在的敘事，從原始檔重走正式抽取與入圖 gate。
- 模型不站在過去判讀；對照讀法是站在今天讀，不是回到過去判讀。
- Phase 8 的進展只數：可開裡寫了對照讀法的檔數（敘事）、由對照讀法與層級反證登記的 watch 條數（等待 registry）、對照讀法記帳的條數與由它登記的前向假說條數（追蹤表）。
- 每日記帳與 APP 時間線仍要先過標旗器考卷 v2、開工前寫 plan、排程變更做 sandbox impact review。
