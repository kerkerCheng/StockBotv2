> **本檔是方向與需求記錄，不是政策。** 判準要升格成規則，必須先實作並量到數字變化，

## 2. 核心判準：「答案回來會改變什麼」

上一版的說法是「lead 優先度 = 它關掉哪一類缺口」。**使用者當場指出這句話本身有漏洞**：
若「缺口」定義成屬性缺得多不多，它就是把「研究量」升到 flow 層重演一次——跟 2026-08-21
剛禁掉的 `evidence` 等級、供應商計數、文件計數是同一個錯誤。

還有一個更難看的自洽問題：**「lead 進來 → 查是不是真的 → source-trace → evidence tier
升級」這個迴圈，唯一單調上升的東西就是 evidence 等級——那是我們自己列為禁用的指標。**
禁了指標，卻沒禁掉專門生產它的迴圈。

**改用結果導向的四級判準：**

| 答案回來時改變的東西 | 價值 | 例 |
|---|---|---|
| **候選集合**（清單上多／少一個名字） | 最高 | `tech:tfln_platform` 找到供應商 |
| **排序**（誰是第一變了） | 高 | 查出 COHR/LITE 對 AXT 有預付款 |
| **出場條件**（disproof 觸發） | 高 | MRVL/GOOGL 案若指向光元件被取代 |
| **只是信心**（排序沒動，只是更確定） | **最低——退化態** | 再找一份文件確認 NVIDIA 真的投了 20 億 |

規則：**動手前先答「答案是 A 會怎樣、是 B 會怎樣」。兩個答案都不改變候選集合與排序 → 降級。**

### 2.1 事件不是敵人，「查傳聞真假」才是

四維度裡的**客戶端資本承諾**本質上就是離散事件（NVIDIA 投 20 億、Micron take-or-pay
押金、POET 發認股權證換訂單），而那是四項裡最難偽造的一項。所以區分不是「事件 vs 結構」：

- 🟢 落在維度 3 的事件（誰掏錢給誰、長約、押金、產能協議）→ **最高價值，直接改排序**
- 🔴 「這則傳聞是不是真的」型 → 通常只動信心，退化態

## 3. pq1 排序：問題是「可以相加」，不是權重調錯

Form 4 拿 12.0 的組成：`base(tier 1) 4.0 + holdings_impact 4.0 + thesis_impact 4.0`。

**每一項單獨看都成立**——它確實是一手來源、確實持有 MU、MU 確實在追蹤中。錯的是三個都成立的
弱理由相加，就能壓過一則講「誰掏 122 億綁誰」的維度 3 事件（後者只是命中的軸比較少）。

**加權總分的病叫補償性：很多個弱理由可以合成一個假的強理由。** 2026-08-12 那次
「12 檔財報季總評擠掉 tier-1 8-K」修的是稀釋係數（`FOCUS_TICKER_CAP`），沒有動到加法本身，
所以同一個病換一種面貌又長出來了。

⚠ **我們已經在別處拒絕過加權總分**：瓶頸排序的設計筆記寫著「排序鍵是明確優先序，不是加權
綜合分數（綜合分數會把證據強度與瓶頸強度壓成一個數字）」。pq1 與 `rank_bottlenecks`
目前是兩套互相矛盾的架構。

## 4. 分工：LLM 做分類，程式做字典序（L15 的直接套用）

三個選項，選 (c)：

| | 做法 | 問題 |
|---|---|---|
| (a) 現行 | 硬編權重相加 | 拍腦袋值、有補償性、從未驗證 |
| (b) LLM 給 0–10 分，程式排序 | **猜測只是從硬編搬進 LLM**；「程式化排序」是裝飾——決定是 LLM 做的；分數每次跑會飄，佇列不可重現、不可稽核 |
| (c) **LLM 封閉字彙分類 ＋ 程式字典序** | ✅ |

**LLM 回答的三題**（語意，regex 做不到；封閉選項）：

| 問題 | 字彙 |
|---|---|
| 誰供應誰／**誰付錢給誰**（方向） | 具名實體 ＋ 方向 |
| 類型 | `維度3資本承諾`／`結構事實`／`財務事實`／`內部人交易`／`純情緒`／`無內容` |
| 答案回來會改變什麼 | `候選集合`／`排序`／`出場條件`／`只是信心` |

方向性那題是唯一能分辨「NVIDIA 掏 20 億給 COHR」與「POET 發認股權證換訂單」的東西。

**三個性質：**
1. **可稽核可重現**——分類結果存回 lead，排序是純函數（L15：解析結果必須落成可稽核的
   確定性紀錄）。
2. **無補償性**——字典序天生不允許弱理由累加。Form 4 分成 `內部人交易`＋`只是信心`
   直接沉底，**不管它是不是一手、不管有沒有持股**。
3. **LLM 不授權任何東西**——只排注意力順序。pq2 核准、evidence tier、graph admission、
   資本 gate 一個都不動。

### 4.1 時機：triage 寫入一次，drain 確定性讀取

- 在 drain 分類 → 每輪重跑 90 則、結果會飄、佇列不可重現
- 在 triage 分類 → 每則算一次、存回 lead、drain 零 LLM 成本且可重現

`skills/signal-triage` 已經是 routine 自動呼叫的純生產端 skill，且本來就要讀 lead 一遍,
**邊際成本接近零**。

### 4.2 四個位置各司其職

| 位置 | 責任 |
|---|---|
| `config/lead_classification.json` | 封閉字彙（taxonomy，留鬆） |
| `skills/signal-triage/SKILL.md` | **判斷**（語意 → LLM） |
| `engine_b/priority.py` | **排序**（字典序，不加法） |
| `skills/alpha-status/SKILL.md` | **呈現**（純消費） |

⚠ `alpha-status` 必須維持純消費，**一個數字都不自己重算**。否則它是在改自己的考卷——
你會分不清「我看到的」跟「排程實際做的」是不是同一件事（L13）。

## 5. 迴路問題：排序解決不了發現

現行迴路：`圖 → rank_bottlenecks → chokepoint_tickers → pq1 加權 → 研究什麼 → 圖`。
**整條線上候選的來源都是圖自己**，圖裡沒有的東西永遠不會被提議。

**排序作用在已存在的集合上；拆解才是產生集合的。** 不可能把一個不存在的節點排到前面。

### 5.1 方向反轉

```
選一個真實系統（實體，不是圖裡的節點）
  → 從一手資料列出它必須有哪些層（spec sheet／teardown／OFC-OCP 論文／專利）
  → 每層問：幾家能做？換掉要多久（合格週期，非交貨週期）？有沒有客戶端資本承諾？
  → 最後才問：我們圖裡有這個節點嗎？
```

**圖從「候選的來源」降級為「已知清單」**，只用來把結果分三堆：

| 結果 | 下一步 |
|---|---|
| 有節點、有供應商 | ✅ 無 |
| 有節點、零供應商 | 🟡 `coverage_gaps` 🔴 已在報 → 找誰供應它 |
| **圖裡根本沒這個節點** | 🔴🔴 **只有拆解會產出這一格** |

### 5.2 誠實的限制：迴路只斷了一半

「選哪個系統」仍是人的決定，且 LLM 列層來自訓練資料、有自己的覆蓋偏差。準確的說法是
**它斷的是「圖 → 候選 → 圖」這個看不見的棘輪，不是所有迴路**。剩下那個（選題）至少是
明擺著、每次都要寫下來的人為決定。

⚠ **推論：不可讓無人值守的週掃自己選題**——它只能從圖和 leads 裡挑，那等於原地繞回。
**人選題、週掃執行積壓題並提名候選**，是唯一不自我打臉的分工。

### 5.3 第一個目標自己跳出來

`coverage_gaps` 的 42 個 🔴 裡有一整群是同一次沒做完的拆解殘骸：
`tech:scale_up_cpo`、`tech:scale_out_cpo`、`tech:silicon_photonics_chiplet`、
`tech:tfln_platform`、`tech:wdm_laser_16ch`、`tech:in_package_optical_io`、
`tech:dsp_1p6t`、`tech:serdes`——**層的名字有了，供應商一個都沒有**。

## 6. 產物持久化判準（回應 §1.2）

> **這個產物如果不存，明天會有誰真的少了東西？**
> 答案若是「只有負責檢查它有沒有過期的那支程式」——**不要存。**

拆解的四種產出各回既有的家，**不新增文件格式**：

| 產出 | 去哪 | 為什麼 |
|---|---|---|
| **層的結構** | **進圖**，走既有 `raw → extract → validate → RA → pq2` | 這才是知識，有 provenance |
| **覆蓋狀態** | **不存** | `coverage_gaps` 隨時可跑；存下來明天就過期 |
| **研究題目** | **進 pq1** | 已有狀態機 |
| **選題與深度** | pq1 item 的 `source` 欄位即可還原 | v1 不另建檔 |

**raw 是這條紀律的執行力，不只是慣例**（2026-08-21 使用者提出）：`library/raw/` 已 tracked
（117 檔在 git）。層要進圖就必須有 raw 撐著，所以「層本身也是 claim」不用靠自律——
**LLM 從記憶裡列出來的層沒有 raw，連進圖的入口都摸不到**，只能變成研究題目。這正是
L6 Gap 4（LLM 從類別詞推出具體實體）的既有防線。

**v1 規格：零新檔案、零 lifecycle、零 freshness cron、零 pq2 佔用。** Session 輸出讀完即棄
（同 daily brief）；週掃跑的話搭本來就留檔的 weekly report 便車。

配套（防止過度保守）：**跑過兩三次後若發現真的在重複推導同一件事，那時才加最小持久化**——
不在跑之前先蓋倉庫。

## 9. 對照初衷（chokepoint-atlas）

原始方法是**系統優先**：選真實系統 → 拆上下游層 → 找出哪一層先卡住 → 才蒐證據。
我們變成**線索優先**：X harvest → triage → 公司 → 補邊。

漂移在目錄結構上看得見：**我們有 `skills/company-onboard`（公司優先入口），
沒有任何系統優先的入口。** §5 的 3c 就是補這一格。

我們比它強的地方（不必妄自菲薄）：跨 session 持久記憶、provenance、四維度判準
（尤其**客戶端資本承諾**是它沒有的）、L14 量測紀律。它有 `scorecard.json` 綜合分數，
我們**刻意拒絕**——那是對的（會把證據強度與瓶頸強度壓成一個數字）。
