## 4. A0：賭注句與對帳日曆

你第一則的原話是「難把敘事組成一個我們在賭的東西」。這件事不缺資料：可開 17 檔都有敘事，「我們賭什麼」中位 204 字、「什麼時候知道」中位 226 字，
反證 71 條、加碼條件 42 條（決策效用審查者 2026-11-21 數的）。缺的是壓成一句與跨檔一覽。

- **句型**（四格、固定順序）：押【哪一層或插槽】的【哪個量】｜翻倍要【哪個營業數字到多少、最晚哪一份文件看得到】｜下一個對帳日【日期：哪一份文件】｜認錯看【哪一條反證】。
- **誰寫**：第 1、2 格由互動研究 session 從這一檔既有的敘事壓成，不新增主張（故事不比依據多主張）；第 2 格只准營業數字，價格不得出現（Phase 7 的既有紅線）。
  第 3、4 格由程式從等待 registry 帶出（最近到期的那一條與它的 id），模型不打日期。
- **缺的照印**：第 2 格寫不成數字 →「翻倍條件還沒寫成數字」；沒有對帳日 →「沒有對帳日」。兩個都是會自己出現的計數。
- **落點**：敘事 ledger 的選填欄（先例：加碼條件、量級格），不升版；候選板與個股頁首屏各印這一句。跨檔一覽依層 id 分組、組內依代號，不排序、不標首選（G1）。
  動敘事 schema 與畫面的逐字 diff 另給（Z2）。
- **對帳日曆（表 C）**：未來 90 天，依日期列出每一檔的反證到期、加碼條件到期、已登記的財報日；來源只有等待 registry，沒登記的不補。它是日曆，不回答哪一檔先買。

樣張（公司與數字都是假的）：

```
甲公司｜可開
押：某層的出貨量——客戶乙把這一代全部交給它
翻倍要：單季營收到 12 億（現在 6.1 億），最晚 2027 年第二季的季報看得到
下一個對帳日：2026-12-10，11 月營收（ew_0000）
認錯看：客戶乙的申報文件列出第二家供應商（ew_0001，2027-03-31 到期）
```

## 5. A1：H16 與「今天的一頁」

### 5.1 先講它量得出什麼（方法論審查者的推算，不是實測）

- 事件數＝宇宙 1,870 檔 × 每年進入三倍狀態的比例 × 8.25 年 × 之後回落四成的比例。三個情境：約 154／324／540 筆；兩個比例都是假設。
- 中情境下：真實的差是 10 個百分點時，判出「支持」的機率約三成；15 個百分點約七成；20 個百分點約九成四。
- **所以這一條量得出 15–20 個百分點以上的差，量不出 10。低情境下所有標記都會是「不足」。** 乾跑（A1a）會先印出事件數；落在低情境就不登記確認型，只交表 A（U6）。

### 5.2 表 A：大跌之後的基準率（描述，不判；零 LLM）

- **列**：回落深度（月收盤第一次 ≤ 高點的 0.6／0.5／0.4）× 孤立或成群（成群月＝當月事件數 ≥ 月均的三倍）；**每一個成群月另外自己一列**。
- **欄**：n；18 個月內月收盤回到事件前高點的比例；18 個月內自 t 收盤曾達 1.67 倍、2 倍的比例；t 起 12 個月內自 t 收盤再跌 30% 的比例；取不到價的檔數與界限（全當沒回到／全當回到）。
- **主表**：台股、事件月 2015-01～2021-03（與 H16 同一批事件，結果窗最晚到 2022-09）。
- **延伸（另表、不合併）**：台股 2000–2014、美股 1995–2021-03。兩張都只有今天還有報價的公司，下市的不在裡面——「回到前高」的比例是**上界**。
  美股代號清單的來源在登記時寫死。陸股、印度、瑞典、加拿大：拿得到完整代號清單才做，否則寫「無法量」。
- **表頭固定印三句**：①可開 N 檔裡台股幾檔、美股幾檔…各適用哪一張（會自己出現的計數）；②成群那幾列的有效樣本是成群月的個數，不是事件數；
  ③這一次是哪一種，這張表答不出來。
- n < 20 的格不印比例，只列個數。

### 5.3 H16：大跌當時的標記，分不分得出之後有沒有回到前高（確認型；台股；預先登記草稿第二版）

**順序**：乾跑規格隨本稿簽 → 零結果乾跑 → 用乾跑的數定標記門檻與標記集合 → 使用者簽判讀線 → 登記（commit 早於任何結果）→ 階段一 → 階段二。

- **一句話**：一檔台股漲過三倍之後第一次自高點回落四成，那個月當下已公布的營收動能、毛利率、同節點廣度（與存貨，若算得出來），分得出它之後 18 個月會不會回到前高。
- **事件**：還原權息月收盤；至少 12 個月價格歷史才判。月收盤自過去 36 個月內最低月收盤起算曾達 ≥ 3 倍；之後第一次月收盤 ≤ 0.6 × 這段漲勢的最高月收盤，那個月＝t。
  三倍狀態在高點後 24 個月沒觸發就解除。同一檔同一段漲勢只記一次。排除金融保險與營建；沿用 H11 的營收基期門檻。事件月 2015-01～2021-03。
- **資料錯誤**：事件抓的是極端值，錯誤濃度高（掃描報告已有兩例）。每列的低點、高點、t 三個月收盤與交易所官方月資料交叉核，不符的剔除並計數；缺價照 H12 的做法分清限流與真的沒有。
- **結果**（階段二才算）：主量＝t 起 18 個月內月收盤曾 ≥ 事件前高點。並列、支持要同向：①18 個月內曾達 t 收盤的 1.67 倍（主量對回落深度機械敏感，這個不會）；
  ②t 起 12 個月對全市場等權的平均超額。四個基線必印：回落深度、漲幅倍數、高點到 t 的月數、大盤同期回落。
- **標記**（只用 t 當月底已可知的資料：月營收到 t−1 月、季報照法定期限；成立＝「壞」；門檻是起始值，由乾跑調到成立率 25–50% 後凍結）：

| # | 標記 | 資料源 | 地位 |
|---|---|---|---|
| M1 | 近三個月營收年增的平均，比再前三個月的平均低 ≥ 10 個百分點（「平均 ≤ 0」另印） | 月營收頁 | 確認型 |
| M2 | 存貨天數（期末存貨 ÷ 單季營業成本 × 91）較去年同季上升 ≥ 20%；只收存貨 ≥ 總資產 5% 的公司 | **彙總表沒有存貨**——要對事件公司逐家抓個別資產負債表；乾跑量可算率與成本 | 乾跑後決定留或移出 |
| M3 | 最近一季毛利率比前四季平均低 ≥ 3 個百分點（「對八季最高」另印） | 損益表彙總 | 確認型 |
| M4 | 合約負債季減 ≥ 20% | 同 M2；這個科目 2018 年後才有（未核一手） | **只印，不判** |
| M5 | 同一櫃買節點（≥ 5 家；多節點取家數最多的）成員裡，近三個月營收年增為正的比例 < 50% | 月營收頁；節點名單是今天的版本，不是當時的 | 確認型 |

- **檢定**：事件季內打亂標籤的排列檢定（10,000 次、種子登記）；效果量＝季內比例差的加權平均（Mantel–Haenszel）；單尾 p ≤ 0.05 ÷ 確認型標記數；區間用以事件月為單位的 bootstrap。合併算的版本只當對照印出。
- **判讀線**（每個標記各判）：
  - **支持**：加權差 ≥ 10 個百分點且方向如預期、p 過線、拿掉事件最多的那一季仍 ≥ 5 個百分點、前後兩段各組 ≥ 30 且同向、兩個並列量同向、依回落深度三分位再分層後方向不變。
  - **削弱**：兩組各 ≥ 150，而且差的 95% 區間上界 < 10 個百分點。
  - **不足**：任一組 < 100，或兩組都有 ≥ 5 筆的季不到 8 個。其餘＝**不確定**。
  - 存活者：缺價事件全當沒回到、全當回到各判一次，判讀翻面就寫「不確定（存活者）」。

| 乾跑就看出全部會不足 | — | 不登記確認型，只交表 A（§14 第 1 支） |

- **期間與已看過的東西（照實寫）**：不是沒看過的期間——H12、H13 用同一批月線算過 2015–2022 的條件報酬；M3 的方向與 H13 報告的事後說法同向。
  舊劇本清單各段對應的櫃買節點成員是這些標記的來源案例：**從判讀線剔除**，含它們的版本另印。M1 另在 2008–2014 做一次（月營收抓得到才做，抓不到寫量不到）；方向相反時判讀降為不確定。
  本稿寫成時沒有算過任何事件、標記或結果。
- **兩階段與順序鎖**：階段一輸出事件表與標記表（不含任何 t 之後的欄），commit 並記 digest；階段二開頭驗 digest。H16 的判讀落帳之前，不執行 §7.4 的層回落標記（同一批封存價格）。
- **不能說**：台股、月頻、2015–2021 以外的任何外推；**不得外推到全題材同跌**——單位是個股事件，歷史上可比的成群月是個位數。一次判讀，不加標記重試。

### 5.4 表 B：可開所騎的層，今天的列（私有；零 LLM）

- **列**：層（依層 id），其下每一檔騎它的可開各一列。不排序、不加總、不亮燈。
- **欄**：這一檔現價對自己高點、距高點幾個月（讓你自己去表 A 找對應的列）；M 標記今天的值；這一層成員等權線對高點；這一層反證已登記與醒來待判的條數；賭注句有沒有。
- **標記欄的規矩**：H16 判讀之前整欄標「未量測」；判讀之後照 §5.3 後果表。每個值旁邊印召回率——沒亮要寫成「沒亮（沒回到前高的事件裡，當時也沒亮的占 a／b）」。
  月營收的標記只有台股有；海外寫「量不到」，有季報的毛利照印但欄頭寫「只在台股量過」。
- 第一版是互動 session 產出、落在私有路徑、在對話裡給你；你說要常看，才做成 APP 的一頁（那時另給畫面的 diff）。

## 6. 確認型與描述型的界線

| | 是什麼 | 能說什麼 | 不能說什麼 |
|---|---|---|---|
| **確認型**：只有 H16 | 台股、零 LLM、判讀線先 commit、結果窗在掃描看過的期間之前 | 「這個標記分得出／分不出」 | 台股以外、月頻以外、全題材同跌 |
| **描述型**：表 A、傳導時差表、結尾標記表、買家口徑時間線 | 人挑的錨與清單、已看過的股價、小樣本 | 「這幾段裡出現過這個數值、這句話」；每格指得回逐字與日期 | 「這個標記有效」「會預測結束」 |

- 描述型的發現要變成依據，只有兩條路：①寫成前向假說進 Phase 7 的帳、往後量；②寫成層級的反證或加碼條件、登記 watch（觸及只提醒）。
  由這些表導出的 watch 一律標「來源：描述型、n＝k、未確認」。**不得直接變成排序、門檻或預設。**
- **敘事只准引個案事實**（而且要先晉升那份文件）；「N 段裡 M 段」這種規律句，只有假說帳有判讀時才准引。回放報告檔頭固定印這一句；P1 在寫入前核對那一步加機械擋，做不到就在 plan 裡寫明只靠紀律。
- 標記與格子的定義在抽取前凍結；看到資料後才想到的一律標「事後」，不與凍結的並列。

## 8. 架構

- **落點**：`library/replay/raw/` 預設忽略，只追蹤清單（網址、sha256、大小、抓取日、發布日與定日方法、`storage_permission`）；被追蹤的每一份回放抽取檔都要有 `storage_permission`（測試斷言）；
  `git ls-files library/replay/raw` 只有清單。試點不做冷備份。
- **對正式系統單向**：除 `replay/` 與它的測試外，全 repo 的 .py 不得 import `replay`（白名單測試，排除 `.venv`）；正式路徑的 .py 不得出現 `library/replay`；不為回放開新的出處前綴。
  出口只有兩個：晉升（從原始檔重走正式抽取與入圖 gate）與回放報告。
- **身分（A2-B1）**：舊公司與輸家進同一份名冊、帶「回放專用」宣告。
  1. `from_path` 永遠載全集，並在全集上驗 id、代號、別名、執行代號唯一；`get_registry()` 回濾過的 view，另開含回放的讀法。
  2. 直讀名冊檔的五處逐一定語意：入圖 prepare 與 validate 把回放專用當未登記、訊息指向晉升；`edgar_watch` 改走預設讀法；直讀的位置用白名單守。
  3. 批次的欄位白名單加這個宣告；回放專用條目跳過 lead 重算與歷史補抓。名冊批次照舊走 pq2，一段一號＝每段一個人工 go。
  4. 晉升＝同一個 id 拿掉宣告，再補跑 lead 重算與歷史補抓；不是新增第二筆。
  5. 預設讀法未命中回放專用 id 時，訊息寫「回放專用、未晉升」。
  - 測試：加一筆回放專用條目前後，預設讀法的 `companies`／`ticker_map`／`company_id_for_ticker` 全等；回放與正式撞代號必 raise；回放專用公司進正式入圖包被拒收；
    含回放的讀法也斷言共用寫法（A2-S6）。
- **現行題材的公司兩邊都有**：兩張表只從回放語料算。引用正式庫的同一份原始檔時，清單記 git blob，雜湊不符就 fail closed；收不收照回放的選文規則。
- **抽取的識別（A2-S1）**：`extract.py` 的 `build_prompt`／`ingest_response` 加兩個參數——`doc_id`（回放一律帶前綴）與整塊實體清單（不讀 Neo4j、也不讀今天的別名表）。
- **事件表（A2-S2）**：sidecar `<doc_id>.events.json`，引用同一份抽取的 `sources[].id`；主檔原樣過正式 validator。
  字彙與 `config/structural_event_kinds.json` 共用（只新增 `capital_commitment`），**紀錄型別分開**：正式端的結構事件由圖屬性差集導出、帶方向；回放事件由文件逐字抽出、帶引文。
  同一個 change 改那份檔的兩個說明欄；sidecar schema 的 kind 清單在驗證時由 config 導出，不抄第二份。
  `invests_in` 邊記「誰投資誰」的關係；事件記「哪一天宣布了多少」，是時變觀測，不回寫邊屬性。
- **節點身分**：每段的層節點在登記表凍結；特徵只數指向登記表節點的邊。
- **不另立定義**：「非自報」「關係人」「as-of」沿用 `query.origin_resolution` 與 `project_assertions_as_of`，回放只寫 JSON→rows 的 adapter；`collapse_assertions` 一律傳空的 resolutions。
- **定日**：`published_at` 沿用 `loader/source_dating.py`，逐份記方法；模型從內文讀出的日期不算。
- **守門清單**：新套件同一個 change 加進四份寫死的清單（層分離、無 LLM API、殭屍 grep、ROADMAP 引用）；提示放 `prompts/`；命名避開 `multi_year`、`calibrat`、`basket`。
- **規則版本**：每段記選案、選文、抽取提示、格子定義的版本；同一張表只收同一版本的段。

## 9. 選文、抽取、抽查

- **只用 ≤ T 的四道防呆**：①在 assertion 與事件層級過濾發布日，不在邊層級（變異測試：一條邊有 T 前的自報與 T 後的客戶端文件，「客戶端印證」必須是 0）；
  ②對手方與海外同業名單只由 ≤ T 的文件產生；③文件上限分 T 前、T 後各自計；④提示不帶今天的圖。
- **選文**：窗＝起漲月前 18 個月到後 24 個月（舊劇本到層回落事件後 12 個月）的年報章節白名單、法說簡報、歷史重訊、財報附註；美股 10-K／10-Q／8-K。照規則抓、不手挑；抓不到的逐家逐型別計數。
  海外用 web search：查詢字串由程式照固定模板組；每家的官方網域在登記表記一格、人確認一次；只收官方網域或交易所公告系統；發布日推不出就排除並計數。
  搜尋不可重現——表裡靠海外文件的格分「台股（機械）／海外（搜尋）」兩欄並附覆蓋率，覆蓋率低的寫「量不到」。
- **批次（A2-B2）**：`claude -p` 零工具，argv 只來自 `crons/llm_step.py`；設定住 `config/replay.json`（`.gitignore` 補 `!config/replay.json`）。
  **批次的全部輸出（提示、回應、抽取草稿、續跑狀態、額度紀錄）只落在一個整目錄忽略的工作區，不持 writer lock**；
  「發布」（搬進被追蹤路徑、更新清單、commit）是互動 session 持鎖、在 daily 寫入窗外做的另一個動作。
  測試：假 runner 跑一輪批次，前後 `git status --porcelain` 逐字相同。每次呼叫後讀額度、過線就停、可續跑。
